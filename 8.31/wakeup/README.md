# wakeup — 고정 회로 웨이크업 학습 모델

설계 명세(`설계명세.html`, 과제계획서 5절)의 학습 모델을 그대로 구현한 것.
파형 → 이진 특징 → START 정렬 → 형판 정합 → WAKE 를 **회로와 같은 순서로**
계산하고, 학습이 끝나면 각 파라미터가 저항값·기준전압·디코더 결선이 된다.

```
config.py     설정. 회로 제약(10 ms 격자, timeout ≤ 63, tau ≥ 1)을 여기서 강제
ste.py        straight-through estimator
frontend.py   파형 -> [B,C,T] 이진 이미지. 학습 대상은 채널 문턱 theta_c 뿐
head.py       형판 M(s,c), 허용 오차 k(s), soft-min AND, k 좌표상승 재적합
model.py      전체 모델 + 손실 + 회로 상수 export
search.py     tau(s) 와 START 조건 합동 탐색 (미분 안 되는 값들)
data.py       Speech Commands v2, 대상 단어 대 나머지(이진)
train.py      학습 진입점
export.py     회로 상수 표 (형판/저항/기준전압/타이밍)
synthetic.py  합성 과제 — 실제 데이터 전에 구조를 검증
tests/        단위 테스트 26개
```

## 돌리는 법

```bash
# 8.31/ 에서
python -m pytest wakeup/tests -q                    # 26개, CPU 로 ~30초
python -m wakeup.train --target on --channels 8 --epochs 30 --tag on_8ch
```

학습은 원격 RTX 박스에서 돌린다. 이 Mac 에는 데이터셋도 CUDA 도 없다.

## 학습 순서 (바꾸지 말 것)

1. **데이터에서 초기화** — 스케일 → 문턱 → 형판 원형 → k
2. **타이밍 탐색** — START 조건과 tau(s)
3. **경사하강** — 형판 M 과 문턱 theta, k 는 주기적으로 다시 탐색
4. **export** — 회로 상수

순서에 이유가 있다. 문턱이 정해져야 이진 특징이 생기고, 특징이 있어야 형판
원형을 뽑고, 형판이 있어야 count 분포가 생겨 k 를 맞출 수 있다.

## 실측으로 정한 것들

합성 과제(`synthetic.py`, 5시드)에서 재어 정한 기본값이다. 실제 음성으로
옮길 때 **다시 재야 한다** — 특히 `ste_clip`.

| 항목 | 발견 | 결론 |
|---|---|---|
| `ste_clip` | tau 탐색 **전**: 0.003 → 0.855, 0.03 → 0.918, 0.1 → 0.680<br>tau 탐색 **후**: 0.949 / 0.980 / 0.973 — 차이가 크게 줄었다.<br>당시 붕괴의 상당 부분은 문턱이 아니라 어긋난 정렬 탓이었다 | **0.03** (0.003 이 낮은 것은 여전) |
| `k` 학습법 | 경사하강에 맡기면 초기에 형판이 무작위라 양성이 전부 탈락 → k 가 바닥까지 내려가고, 이후 양성이 여유롭게 통과해 다시 올릴 기울기가 사라진다 | **좌표상승 탐색** |
| `k` 목적함수 | `TPR - w·FPR` 은 w ≥ 2 에서 "전부 거부"(TPR 0)가 최적이 됨 | **FPR 상한 아래 TPR 최대** |
| AND 구현 | 시그모이드 곱은 P→1 에서 `log(1-P)` 가 무너져, 정작 고쳐야 할 확신에 찬 오검출에서 기울기가 사라짐 | **soft-min 로짓 + BCEWithLogits** |
| `tau` | 고정(추측)하면 acc 0.762±0.179, TPR 0.578<br>탐색하면 acc 0.979±0.017, TPR 1.000 | **반드시 탐색** |
| 형판 초기화 | 원형 초기화는 무작위 대비 이득 없음 (0.742 vs 0.800). 분산의 원인은 초기화가 아니라 tau 였다 | 원형 유지(무해), tau 탐색이 본질 |
| START 조건 | 지터로 고르려 했으나 틀렸다 — 클립마다 발성 시각이 달라 START 위치의 표준편차는 검출 지터가 아니다. 실제 음성엔 정답 onset 도 없다 | **최종 목적함수로 tau 와 합동 탐색** |

합성 과제 최종: **acc 0.981 ± 0.009, TPR 0.998 ± 0.004, FPR 0.035 ± 0.017** (5시드, 최저 0.973)

## 실제 음성 — 확정 구성

`sheila`, **8채널**, **상태 2**, 채점 창 ±2, timeout 60, START `k=1 × 3프레임`,
τ = [2, 10] (20 / 100 ms).

**실행 명령을 반드시 같이 적을 것.** 아래 표를 만든 실행은 이것이다.

```bash
python -m wakeup.train --target sheila --channels 8 --states 2 \
    --match-window 2 --epochs 30 --on-rate 0.15 --seed 1 --tag final8_s1
```

종전에 이 명령을 적지 않아 `--on-rate 0.15` 가 누락된 채 재현했고, TPR 이
0.575 에서 0.394 로 4σ 어긋났다. 원인을 찾는 데 실험 세 벌(15회 학습)을
버렸다. 재현이 안 되면 `--diff-config` 로 **저장된** config 를 비교할 것 --
기억이나 이 문서가 아니라 체크포인트가 근거다.

(그 뒤 `init_on_rate` 기본값을 0.15 로 올렸으므로 지금은 플래그 없이도 같다.)

| 지표 | 값 |
|---|---|
| 클립 검출률 / FPR | **0.575 ± 0.021 / 0.027 ± 0.010** (시드 5회) |
| 연속 검출률 | **60.6 ± 4.6 %** |
| 그 지점의 FA/h | 약 81 |
| 부품 | 비교기 2, 래치 2, 형판 저항 14~16, 분압 4 |
| 판정 여유 | 0.113~0.150 V |

동작점은 `k`로 고른다 (= 분압 저항 두 개):

| k | 검출률 | FA/h |
|---|---|---|
| [8, 7] | 12.3% | 0.0 |
| [8, 6] | 16.0% | 6.0 |
| [7, 7] | 37.7% | 17.9 |
| [7, 6] | 59.4% | 80.7 |

## 시연자 목소리 — 측정값 (voice/test, 21발화)

검출률은 시연자 녹음에서, FA/h 는 Speech Commands 스트림에서 잰다. 오경보를
만드는 것은 주변의 말소리이므로 출처가 달라야 맞다. **하나의 '정확도'로
합치지 말 것.**

| FA/h 예산 | 검출률 | 이득 | timeout | k |
|---|---|---|---|---|
| ≤ 10 | 9.5% | 1.00 | 28 | [8, 7] |
| ≤ 30 | **42.9%** | **1.00** | **60** | **[4, 7]** |
| ≤ 100 | 42.9% | 1.00 | 60 | [4, 7] |

10 과 30 사이에 절벽이 있다 (0.0 다음이 바로 29.9). k 격자가 그 구간에서
성기다는 뜻이고, 상태를 늘리면 해상도가 올라갈 수 있다.

시연자의 목소리는 화자별 분포에서 **어려운 쪽**이다 (평균 60% 대 42.9%).

## 구조 — 상태 2 로 확정 (2026-10-13)

같은 채점 창(±2)에서 다시 재니 4상태가 **더 나빴다**.

| | 상태 2 | 상태 4 |
|---|---|---|
| TPR | **0.575** | 0.481 |
| FPR | 0.027 | 0.026 |
| 비교기 / 형판 저항 / 분압 | 2 / 16 / 4 | 4 / 32 / 8 |

이유는 출력에 그대로 나온다 — 네 상태 중 **둘이 스스로 꺼졌다**.

```
s1: 1.000 / 1.000   k=1, V_TH 0.206V   (항상 통과 = 배선 없는 것과 같음)
s3: 1.000 / 1.000   k=1
```

fit_k 가 FPR 상한 아래에서 TPR 을 최대화한 결과가 "두 상태만 쓴다" 였다.
최적화기가 2상태로 충분하다고 답한 셈이다. 부품 두 배를 낼 이유가 없다.

## 프레임 클럭 — ÷256 확정 (2026-10-14)

```bash
python -m wakeup.train --target sheila --channels 8 --states 2 \
    --match-window 2 --epochs 30 --on-rate 0.15 --frame-ms 7.8125 \
    --repeat 5 --tag f256_ok
```

| 분주비 | 프레임 | TPR | FPR | START |
|---|---|---|---|---|
| — | 10.0 ms | 0.515 ± 0.082 | 0.029 | 0.924 |
| **÷256** | **7.8125 ms** | **0.519 ± 0.065** | 0.031 | 0.927 |
| ÷512 | 15.625 ms | 0.431 ± 0.027 | 0.027 | 0.925 |

÷256 과 10 ms 는 구분되지 않는다(차이 0.004, 편차의 1/16). ÷512 만 확실히
나쁘다 — 5시드 최대값 0.462 가 다른 둘의 평균보다 낮다.

**32.768 kHz 손목시계 수정 + 74HC4060 Q8 로 간다.** 10 ms 를 지키려면
3.2768 MHz 수정이 필요한데, 잃는 것 없이 그 조달 위험을 없앨 수 있다.

### on_rate 0.15 의 대가 — START 재현율 0.995 -> 0.925

켜짐률을 낮추면 형판 판별력은 오르지만 START 가 덜 선다. 양성의 7~8% 가
시작조차 못 하고, 그건 형판이 아무리 좋아도 못 잡는 손실이다. 타이밍
탐색에서 `start_k >= 2` 가 전부 min_recall 미달이 되어 **start_k=1 로
못박힌다**(확정 구성이 이미 쓰던 값이라 퇴보는 아니다).

start_k=1 은 "채널 하나라도 켜지면 START" 다. START 자체는 LED 를 켜지
않고 채점 창만 여는 것이므로 직접 오경보가 되지는 않지만, 두 가지가 따른다:

- 채점 기회가 늘어 FA/h 가 오른다 (측정값에 이미 반영돼 있다)
- **잡음 START 가 진짜 발화를 가린다** — `run_ff` 가 서 있는 동안 새 START 는
  무시되므로(gatelevel.py), 잡음이 먼저 START 를 세우면 timeout 동안
  (÷256 에서 219 ms) 진짜 단어를 못 받는다

`on_rate` 는 0.0(전부 통과 실패)과 0.15 두 점만 재봤다. 0.20~0.30 에서
START 가 회복되면서 TPR 이 유지되는지는 **아직 모른다**.

## 화자 종속 GSC 학습은 불가능 (2026-10-13)

```
'sheila' 발화 2022개, 화자 1442명, 1인당 평균 1.40개
화자의 68.9% 가 1개, 93.3% 가 2개 이하, 최대 6개
```

시연자 녹음 64발화도 모자랐는데 GSC 는 1인당 최대 6개다. 이 길은 닫혔다.

## enrollment — 세 번 시도하고 접었다

| 방식 | 결과 |
|---|---|
| 섞기 (enroll_frac 0.3) | 시험 TPR 0.575 -> 0.373. s2 가 음성의 58% 통과 |
| 화자 종속 (enroll_only) | FA/h ≤ 30 도달 불가. ≤ 100 에서 23.8% (기준선 42.9%) |
| 기준선 (화자 독립) | **42.9% @ 29.9 FA/h** ← 그대로 쓴다 |

화자 종속이 진 이유는 k 가 빡빡해서가 아니다 (연속 지표로 다시 골라도 졌다).
**지름길** 때문이다: 양성은 시연자의 마이크·방에서 나오고 음성은 Speech
Commands 에서만 나오니, 단어를 배우는 것보다 녹음 채널을 배우는 게 쉽다.
형판이 `1 1 1 1 1 1 1 1`(그냥 크고 넓은 소리)로 수렴한 것이 그 흔적이다.

막으려면 **같은 마이크·같은 방의 음성**이 필요하다 — `--enroll-neg`.
아직 녹음 전이다.

## 실제 음성에서 고친 것들

| 증상 | 원인 | 대처 |
|---|---|---|
| TPR 0.978 / FPR 0.981 (전부 통과) | 켜짐률 57% — 문턱을 분포 한가운데 놓았다 | `init_on_rate` (분위수 초기화) |
| τ가 110 ms 안에 몰림 | START 에서 멀어질수록 정렬 오차가 쌓인다 | 채점 창 (PASS 를 셋 우세 래치로) |
| START 0.873 → 0.343, 손실 발산 | θ 가 이진 특징과 START 를 동시에 정하는데 손실은 앞쪽에만 기울기가 있다 | **θ 동결** |
| 손실이 30에폭 평평 | 학습용 k=16 은 전 채널 일치라 양성도 못 넘는다 | Youden J 로 학습용 k |
| 상태 셋이 형판을 못 배움 | fit_k 가 k=1 로 두면 soft-min 이 그 상태에 기울기를 안 보낸다 | 학습 중 k 고정 |
| 곡선에서 검출률 60% → 18% | fit_k 는 **클립** 지표를 최적화하는데 우리는 **연속** 지표가 필요하다 | 연속 지표로 k 격자 탐색 |

## 틀렸던 예측

- **2상태가 4상태와 같을 것** — 창까지 같이 바꿔 비교가 오염됐다. 같은 창에서
  다시 재니 2상태가 FPR 2.5배 우위였다(결론은 같지만 근거가 달랐다).
- **형판 공유 가능** — 시드 0에서만 두 형판이 같았다. 5시드 중 1회. 철회.
- **16채널이 동작점 해상도에서 유리** — 모든 FA/h 예산에서 8채널이 같거나 나았다.
- **timeout 은 효과 없음** — 합성에서 안 보였을 뿐, 실제로는 모든 k 에서 FA/h 를 낮춘다.
- **FA/h 약 300/시간** — 암산이 무음 구간을 빼먹었다. 실측 81.
- **형판 공유로 부품을 반으로 줄일 수 있다** — 두 번째 철회. 15시드(10 ms /
  7.81 ms / 15.6 ms 각 5회) 중 **1회**만 두 형판이 같았다. 비교기 2, 형판
  저항 14~16, 분압 4 로 설계한다.
- **tau 탐색이 고정 tau 를 크게 이긴다** — 그 격차(합성 과제 0.762 대 0.979)는
  문턱 초기화가 0.0 이던 시절의 것이다. 0.15 로 고치자 합성에서는 고정 tau 도
  1.000 이 나온다. 당시 붕괴의 상당 부분이 tau 가 아니라 문턱 탓이었다
  (ste_clip 때와 같은 패턴 -- 두 번째로 같은 함정에 빠졌다). 실제 음성에서는
  tau 탐색이 여전히 결정적이다.
- **PreAMP 이득이 싼 지렛대** — `--eval-wav` 의 이득 훑기에 FA/h 축이 없어서
  "이득 2.0 에서 16/21" 로 보였다. 오경보를 세니 반대였다: 이득을 올리면
  검출보다 FA/h 가 더 빨리 올라, 예산 안에서는 k 로 도로 갚느라 검출이
  43% -> 5% 로 무너진다. **이득 1.0 이 최적**이다 (레벨 맞추기로 이미
  제자리였다). timeout 은 반대로 진짜였다 — 같은 지점에서 28 대 60 이 33% 대 43%.
- **enrollment 이 시연자 검출을 올린다** — 세 방식 모두 기준선보다 나빴다. 위 표.
- **상태를 늘리면 AND 가 늘어 FPR 이 준다** — 같은 창에서 재니 FPR 은 그대로
  (0.026 대 0.027) 이고 TPR 만 9.4pp 떨어졌다. 남는 상태는 k=1 로 꺼진다.
- **enrollment 녹음을 그대로 쓰면 된다** — 파일 전체를 피크 0.25 로 맞췄더니
  발화 RMS 가 데이터셋의 1/4 이었다. START 가 94% -> 73.8% 로 무너져 양성의
  30% 가 통째로 버려졌다. 발화 RMS 중앙값을 데이터셋에 맞춰야 한다(이득 4.09배).

## 아직 안 한 것

- `--enroll-neg` 녹음 (같은 마이크·방의 '다른 말') 후 화자 종속 재시도
- `filterbank="spice"` — 동료 SPICE 행렬이 확정되면 `--spice-matrix` 로
- `theta_c` 를 VTHR 10 mV 격자에 양자화한 뒤 재평가
- 50핀 ICD, 부품표 생성기
- 소자 공차 몬테카를로
- 연속 오디오 FA/h 를 여러 소음 조건에서 세분화
