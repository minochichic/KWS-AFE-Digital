`8ch_wakeup_digital_stage_1V8_design_report.docx` 의 판별부에 맞춘 학습 방법과 알고리즘.
**이 폴더 안에서만 작업한다** (본 리포의 FPGA/BNN 작업과 별개).

## 1. 무엇이 바뀌었나

### (a) 모델이 106,240개 연속 가중치 → 약 50개 이산 파라미터

| 파라미터 | 개수 | 값 | 회로에서 |
|---|---:|---|---|
| 채널 임계값 `θ_c` | 8 | 연속 | R7/R8 분압 8쌍 |
| START 조건 | ≤8 | {1,0,X} | AND/NOR 배선 |
| 샘플링 시각 `τ_s` | 4 | 정수 (10 ms 격자) | 디코더 카운트 |
| 형판 `M[s,c]` | 32 | {1,0,X} | 4.7 MΩ 배선 |
| 허용 개수 `k_s` | 4 | 정수 | 기준전압 분압 |
| 타임아웃 | 1 | 정수 | 디코더 카운트 |

4×8 ternary 형판의 정보 용량은 최대 `32·log₂3 ≈ 50 bit`. 기존 BNN 은 입력만으로
프레임당 11.16 bit × 128 프레임을 받았다. **경사하강법이 불가능할 뿐 아니라 필요도
없다** — 대부분 전수 탐색하거나 그냥 세면 된다.

### (b) 12-class 분류 → 단일 키워드 **검출**

지표가 accuracy 가 아니라 **검출률(TPR)** 과 **시간당 오검출(FA/h)** 이다.
always-on 기기에서는 "말 안 했는데 깨어남"이 훨씬 크게 체감되므로, 허용 FA/h 를
먼저 정하고 그 지점의 TPR 을 본다.

### (c) 재사용 / 신규

**그대로 쓴다**: AFE 시뮬 전체(채널 수만 16→8), SPICE 필터뱅크 추출,
임계값→R7/R8 변환, 비교기 오프셋 분석.
**버린다**: BNN, 학습 루프, RTL.
**새로 만든다**: START 정렬 + 형판 적합 + 상태기계 평가. **한 모듈이면 된다.**

## 2. 표기

AFE 시뮬을 통과한 클립 하나는 `X[c, t] ∈ {0,1}`, `c = 0..7`, `t` 는 **10 ms 프레임**.
프레임 주기는 회로의 100 Hz 카운터와 같아야 하므로 `envelope_win_ms = 10` 고정.

- `P` : 대상 단어 클립 집합 (양성)
- `N` : 비대상 클립 집합 (다른 단어 · 무음 · 소음)
- `C` : 합성 또는 녹음된 **연속 오디오** (§7)

## 3. START — 시간 원점이지 wake-up 스위치가 아니다

### 3.1 왜 필요한가

형판은 "**발화 시작 후 250 ms 에 채널이 이렇게 생겼다**"는 형태다. 원점이 없으면
250 ms 가 무엇 대비인지 정의되지 않는다. 회로 전체는 이미 always-on 이고
(아날로그 전단은 한 번도 안 잔다) IDLE 은 **카운터만 멈춘 상태**일 뿐이다.

원점 없이 하려면 채널별 과거 프레임을 들고 매 tick 마다 형판을 훑어야 한다 —
8채널 × 60프레임 = **480 bit 시프트 레지스터**, 8 bit IC 로 60개. 대회 규모에서
비현실적이다.

### 3.2 ⚠️ 비대칭 — 헛 START 는 싸고, 놓친 START 는 치명적이다

| | 대가 |
|---|---|
| **헛 START** | 카운터 한 사이클. WAKE 는 형판 4개가 다 맞아야 나오므로 **오검출로 이어지지 않는다** |
| **놓친 START** | 그 발화는 **영영 검출 불가**. TPR 의 천장 |

→ **재현율을 1.0 가까이 놓고, 정밀도는 전력이 감당되는 선까지만 낮춘다.**
"8채널 중 2개 이상 켜짐" 같은 아주 헐거운 조건도 후보다.

### 3.3 진짜 판정 기준은 재현율이 아니라 **지터**다

재현율이 높은 후보는 여럿 나온다. 그중에서 고르는 기준은 **START 가 단어의
같은 지점에서 터지는가**이다. 발화마다 다른 지점에서 터지면 `τ_s` 의 형판이
뭉개져 쓸모없어진다.

절대 시각을 알 필요는 없다 — 형판이 START **상대** 시각으로 학습되므로
**분산만 작으면 된다.**

### 3.4 알고리즘: 전수 탐색

후보는 채널 부분집합 `S ⊆ {0..7}`, `|S| ≤ 4`, 각 채널의 극성 `p_c ∈ {0,1}`.
조건은 `S` 의 모든 채널이 극성과 일치할 때 참.

```
경우의 수 = Σ_{k=1..4} C(8,k)·2^k
          = 16 + 112 + 448 + 1120 = 1,696
```

**전수 탐색이 그냥 된다.** 각 후보에 대해:

```python
for cand in all_candidates():                    # 1696개
    fire_p = [first_fire(cand, X) for X in P]    # 양성에서 첫 발화 프레임
    recall = mean(f is not None for f in fire_p)
    if recall < 0.98: continue                   # 재현율 먼저 거른다

    # 지터: 클립 에너지 onset 대비 START 시점의 산포
    off    = [f - onset(X) for f, X in zip(fire_p, P) if f is not None]
    jitter = std(off)

    rate = fires_per_sec(cand, C)                # 연속 오디오에서의 발생률
    if rate > RATE_BUDGET: continue              # 점유율/전력 상한

    score[cand] = jitter                          # 작을수록 좋다
best = argmin(score)
```

`onset(X)` 는 클립 전체 에너지가 처음 문턱을 넘는 프레임. **절대 정확할 필요 없다** —
모든 클립에 같은 정의를 쓰면 그 오차는 상수 오프셋이 되어 지터에 안 들어간다.

`first_fire` 는 **첫 발화만** 본다. 하드웨어에서 RUN 이 첫 edge 에 래치되고
타임아웃까지 유지되기 때문이다 (§6).

### 3.5 타임아웃을 짧게 잡아야 하는 이유

카운터가 **하나뿐이라 동시 시도가 안 된다.** 헛 START 로 카운터가 도는 동안
진짜 발화가 들어오면 놓친다. 그래서 타임아웃은 `τ_4` 직후로 짧게 잡아 점유
시간을 줄인다. 이게 §3.2 의 "헛 START 는 싸다"를 실제로 싸게 만드는 조건이다.

## 4. 정렬

```python
def align(X, start_cond, span):
    t0 = first_fire(start_cond, X)
    if t0 is None: return None
    return X[:, t0 : t0 + span]      # 모자라면 0 패딩
```

이 재색인이 기존 파이프라인에 **없던 유일한 개념**이다. 예전에는 고정 1초 창을 봤다.

## 5. 샘플링 시각과 형판

### 5.1 형판은 탐색이 아니라 집계다

시각 `τ` 가 정해지면 각 채널의 최적 비트는 계산된다:

```python
p1 = mean(A[c, τ] for A in aligned(P))        # 양성
p0 = mean(A[c, τ] for A in aligned(N_started)) # 음성 중 START 가 터진 것만
d  = p1 - p0

M[s,c] = 1  if d >  delta
         0  if d < -delta
         X  otherwise            # don't-care, 저항 하나를 아낀다
```

**`N_started` 가 중요하다.** 형판 단계에 도달하는 것은 START 가 터진 음성뿐이다.
전체 음성으로 통계를 내면 실제로 만나지 않을 분포에 형판을 맞추게 된다.

`delta` 는 don't-care 를 얼마나 넉넉히 둘지 정하는 손잡이다. 크게 잡으면 채널이
적게 쓰여 저항이 줄고 잡음도 준다. 스윕한다.

### 5.2 시각은 탐욕적으로 — AND 라서 조건부로 골라야 한다

네 시각은 **AND** 로 묶이므로 독립이 아니다. 각각 따로 좋은 시각 넷을 고르면
같은 실패만 네 번 잡는다. 살아남은 것들 위에서 다음을 고른다:

```python
times, tmpl = [], []
surv_p, surv_n = aligned(P), aligned(N_started)

for s in range(4):
    best = None
    for tau in range(TAU_MIN, TAU_MAX):            # 10 ms 격자
        if any(abs(tau - t) < MIN_GAP for t in times):
            continue                                # 인접 프레임은 서로 중복
        M   = fit_template(surv_p, surv_n, tau)     # 5.1
        k   = best_tolerance(M, surv_p, surv_n, tau)
        sep = pass_rate(surv_p, M, k, tau) - pass_rate(surv_n, M, k, tau)
        if best is None or sep > best.sep:
            best = (tau, M, k, sep)

    times.append(best.tau); tmpl.append(best.M)
    surv_p = [A for A in surv_p if passes(A, best)]  # ← 통과한 것만 남긴다
    surv_n = [A for A in surv_n if passes(A, best)]
```

`MIN_GAP` 은 3~5 프레임 정도. 인접 프레임은 엔벨로프 시상수 때문에 거의 같은
값이라 붙여 놓으면 한 시각을 두 번 쓰는 셈이 된다.

`TAU_MAX` 는 8 bit 카운터라 255 이하. 단어 하나면 60~80 이면 충분하다.

## 6. 상태기계 — 이게 곧 회로다

평가는 클립 단위 분류가 아니라 **회로와 같은 상태기계**를 돌려야 한다.
연속 오디오 위를 그냥 흐르므로 §7 의 FA/h 도 이 코드로 나온다.

```python
state, t0, passes = IDLE, None, [False]*4
wakes = []

for t in range(T):
    if state == IDLE:
        if start_cond(X[:, t]):
            state, t0, passes = RUN, t, [False]*4
    else:
        tau = t - t0
        for s in range(4):
            if tau == times[s]:
                passes[s] = n_match(tmpl[s], X[:, t]) >= k[s]
        if tau == timeout:
            if all(passes): wakes.append(t)
            state = IDLE
```

하드웨어와 1:1 이다. `t0` = RUN D-FF, `passes` = PASS1~4 D-FF,
`tau == times[s]` = 디코더, `all(passes)` = 최종 AND.

> **주의**: 실제 회로의 WAKE 는 조합 논리라 PASS4 가 써지는 순간 바로 올라간다.
> 타임아웃까지 기다리지 않는다. 위 코드는 타임아웃에서 판정하는데, 결과는 같고
> **시각만 다르다.** 시연에서 반응 지연을 재려면 PASS4 시점으로 옮긴다.

## 7. 연속 오디오 — 필수는 아니지만, 데모 전에는 필요하다

### 7.1 없이도 되는 것 / 안 되는 것

| | 클립만으로 |
|---|---|
| 설정 A vs B 비교, 형판·시각·허용개수 선택 | ✅ 된다 |
| **시간당 오검출 횟수** | ❌ 안 된다 |

1초 클립은 시도 1회다. 연속 오디오에서는 START 가 분당 여러 번 터지고
**그 횟수가 곧 시도 횟수**라, 클립 단위 오검출률을 시간당으로 환산할 수 없다.

### 7.2 값싼 대안: 합성

GSC 의 비대상 단어를 무작위 간격으로 이어붙여 연속 오디오를 만든다. 공짜다.

```python
def synth_stream(clips, minutes, speech_density=0.35, noise=None):
    out = []
    while len(out) < minutes*60*SR:
        out.append(random.choice(clips))                    # 단어 하나
        gap = int(SR * random.expovariate(1/mean_gap(speech_density)))
        out.append(zeros(gap))
    s = concat(out)
    if noise is not None: s += scale(noise, target_snr)
    return s
```

잔향도 중첩도 없지만 **시도 횟수를 낼 수 있다**는 게 핵심이다.

### 7.3 진짜 위협은 소음이 아니라 사람 말소리다

에어컨 소리는 8채널 패턴이 단어와 안 닮았다. **다른 사람 대화는 닮았다.**
GSC 의 `_background_noise_` 는 설거지·수돗물·화이트노이즈 계열이라 이 부분을
못 덮는다. §7.2 의 합성(비대상 **단어**를 이어붙임)이 그래서 오히려 더 적절하다.

### 7.4 실제 녹음은 발표 직전 10~30분

목적이 통계적 신뢰구간이 아니라 **"발표장에서 몇 분에 한 번씩 깨어나지는 않는다"**
확인이다. 발표장과 비슷한 조건(사람 말소리, 공조, 노트북 팬)으로 10~30분이면 충분하다.

## 8. 임계값 — 좌표 상승

`θ_c` 는 다른 모든 단계와 얽혀 있어 한 번에 못 정한다.

```
1) 초기화   θ_c = quantile(env_c over P∪N, 1 - r),  r ≈ 0.25
2) §3~§5 를 한 바퀴 돌려 START·시각·형판·허용개수를 얻는다
3) 채널 하나씩:
      θ_c 를 ±step 흔들어 §5(형판 재적합)와 §6(평가)만 다시 돌린다
      -- START 는 고정. 재적합이 싸서 8채널 × 2방향이 금방 끝난다
      DET 가 좋아지면 채택
4) 개선이 멈출 때까지 3) 반복
```

`r ≈ 0.25` 는 본 프로젝트 16채널 실험에서 발화율 7.8~36.4% 일 때 채널이
죽지도 포화하지도 않았던 범위에서 가져왔다.

## 9. 회로 제약 — 이걸 모르고 최적화하면 만들 수 없는 답이 나온다

| 제약 | 근거 | 학습에 주는 조건 |
|---|---|---|
| 시간 격자 10 ms | 100 Hz RC 발진 | `τ_s` 는 정수 |
| 샘플링은 bin 중앙 | §6.3 glitch 방지 | 실제 시각 = `τ_s`×10 ms + 5 ms |
| `τ ≤ 255` | 8 bit 카운터 | 여유 있음 |
| 상태 4개 | TLV7034 4채널 | 늘리면 IC 추가 |
| **점수 = 일치 개수** | 저항 전부 4.7 MΩ | **채널 가중치 불가** |
| 카운터 1개 | 부품 수 | **동시 시도 불가** → 타임아웃 짧게 (§3.5) |
| 비교기 오프셋 8 mV | TLV7034 max | 인접 점수 간격보다 작아야 함 |

### 9.1 ⚠️ don't-care 를 쓰면 기준전압이 상태마다 달라진다

저항 평균 노드의 전압은

```
V_score = VDD × n_match / m        (m = 그 상태에서 실제로 연결된 저항 수)
```

**분모가 `m` 이다.** don't-care 로 채널을 빼면 `m` 이 상태마다 달라지므로
설계 보고서 §8 의 단일 기준전압 1.4625 V (8채널 전부 사용 가정) 를 네 상태에
공통으로 쓸 수 없다.

**해결은 싸다.** TLV7034 는 비교기 4개가 독립이고 각자 − 입력을 가지므로
**상태별 분압 4쌍**을 두면 된다 (저항 8개 추가):

```
VTH_s = VDD × (k_s − 0.5) / m_s
```

`k_s` = 그 상태의 허용 일치 개수, `m_s` = 연결된 채널 수.
학습이 상태마다 다른 `m_s`, `k_s` 를 자유롭게 고를 수 있게 된다.

대안은 모든 상태가 같은 채널 수를 쓰도록 강제하는 것인데, 학습을 불필요하게
묶으므로 권하지 않는다.

### 9.2 마진 확인

`m_s` 가 작아지면 인접 점수 간격 `VDD/m_s` 가 커져 오히려 유리하다.
`m=4` 면 간격 450 mV, `m=8` 이면 225 mV. 둘 다 TLV7034 오프셋 8 mV 와
저항 1% 공차 대비 넉넉하다. **작은 `m` 이 마진에도 좋다.**

## 10. 정확도 기대치

**기존 0.825 와 비교하면 안 된다.** 과제가 다르고(12-class 분류 vs 단일 검출)
모델 용량이 세 자릿수 작다.

- 유리: 문제가 훨씬 쉽다. 한 단어만.
- 불리: 50 bit 로 화자·속도·잡음 변이를 감당해야 한다.

**미측정이다.** §3~§8 을 돌려봐야 안다. 다만 심사 기준이 정확도 수치가 아니라
제약 안에서의 창의성과 동작하는 시작품이므로, 조용한 실내에서 안정적으로
동작하고 오검출이 드물면 충분하다.

그리고 이 구조는 **왜 동작하는지 설명할 수 있다** — 형판 32개를 표로 보여주고
회로도의 저항 배선과 1:1 대응시킬 수 있다. 가중치 10만 개로는 못 하는 일이다.
