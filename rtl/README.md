# RTL 설계 노트

`docs/ICD.md`가 아날로그 경계를 정한다면, 여기는 **경계 오른쪽의 설계 결정**을 적는다.
결정을 바꾸려면 여기부터 고친다.

---

## 1. 제로 패딩은 −1이 아니다 ★

가장 조용히 틀리기 쉬운 지점이다. 골든 벡터로 확인했다 (2026-08-16).

`b1_s0_dw`는 `k=13, padding=6`이다. 프레임별 실측 `max|acc|`:

| 프레임 | 0 | 1 | 2 | 5 | 6 | 63 |
|---|---|---|---|---|---|---|
| `max\|acc\|` | 7 | 8 | 9 | 12 | 13 | 7 |
| 유효 탭 수 | 7 | 8 | 9 | 12 | 13 | 7 |

**정확히 일치한다.** PyTorch conv1d의 패딩은 0이고, 0은 곱해서 **0을 기여**한다.
`{-1,+1}` 인코딩에서 −1이 아니다.

### 그래서 MAC 에 무엇을 넘겨야 하나

`2·popcount(XNOR) − N` 은 **항당 0 기여를 표현할 수 없다.** 모든 항이 ±1 이라고
가정하기 때문이다. 패딩 탭은 **N 에서도 빠져야** 한다:

```
n_valid = 그 프레임의 유효 탭 수   (가운데 13, 왼쪽 끝 7, 오른쪽 끝 7)
```

`kws_bin_mac` 은 `n_valid` 를 받고 **낮은 n_valid 비트**를 마스크한다. 그런데
왼쪽 가장자리의 유효 탭은 **높은 쪽**이다 (t=0 이면 탭 6..12). 그대로 넘기면 틀린
탭을 센다.

**유효 탭은 항상 연속 구간**이므로, 활성과 가중치를 **같이 오른쪽으로 시프트**해
유효 구간을 비트 0 부터 시작하게 만들면 기존 MAC 이 그대로 맞는다:

| 프레임 | 시프트 | `n_valid` |
|---|---|---|
| `t < P` (왼쪽 끝) | `P − t` | `K − (P − t)` |
| 가운데 | 0 | `K` |
| `t ≥ T − P` (오른쪽 끝) | 0 | `K − (t + P − (T−1))` |

> 시프트를 활성에만 걸고 가중치에 안 걸면 **탭 정렬이 어긋난다.** 값이 그럴듯하게
> 나오고 가장자리 프레임만 틀리므로, 골든 벡터 없이는 못 찾는다.

## 2. 활성 메모리는 프레임-메이저 (결정: 2026-08-16)

한 워드 = **한 프레임의 모든 채널** (채널 c 가 비트 c, LSB first).
`export/golden.py` 의 `*_out.hex` 패킹과 **같은 레이아웃**이라 골든 벡터를 그대로
비교할 수 있다.

| | 이 레이아웃에서 | 대안(채널-메이저) |
|---|---|---|
| **pointwise** (1×1, 채널 방향) | 워드를 그대로 스트리밍 — C/32 사이클 | 트랜스포즈 필요 |
| **depthwise** (K, 시간 방향) | K 프레임 라인버퍼 + 비트 게더 | 워드 그대로 |

둘 중 하나는 반드시 대가를 치른다. 프레임-메이저를 고른 이유:

1. **pointwise 가 훨씬 많다** — 이진 층 15개 중 pointwise 계열이 다수고, 항 수도
   64~128 로 depthwise(13~29)보다 크다.
2. **골든 벡터와 레이아웃이 같다** — 테스트벤치가 변환 없이 비교한다. 변환 코드는
   그 자체로 버그가 날 자리다.
3. depthwise 의 라인버퍼는 K×C 플립플롭(13×128 = 1664)으로 작다.

## 3. 모듈 분해

`kws_tcs_sub` 를 한 덩어리로 만들지 않는다. depthwise 와 pointwise 는 **메모리
접근 패턴이 다르고**, 골든 벡터도 `b1_s0_dw_*` / `b1_s0_pw_*` 로 **따로 있다**.
따로 만들면 따로 검증된다.

```
kws_bin_mac   ✅  2·popcount(XNOR) − N
kws_dw_conv   ✅  라인버퍼 + 비트 게더 + 시프트/n_valid + threshold
kws_pw_conv   ✅  프레임 워드 스트리밍 + threshold
kws_tcs_sub   🔵  dw → pw 배선  (시뮬 대기)
kws_block     ⬜  sub ×2 + residual add (정수 영역)
kws_top       ⬜  21개 층 시분할
kws_frame_ctrl ⬜ 2FF 동기화 + sticky OR (ICD §5)
```

## 4. 코딩 규약

- **Verilog-2005 서브셋.** iverilog·Verilator·Vivado 가 똑같이 해석하게.
  `$countones`·`logic`·`always_ff` 안 씀. XSim 이 본선이 되면 재검토.
- **폭은 명시적으로.** 암묵적 확장·잘림 금지. `verilator --lint-only -Wall` 이
  게이트다 (`rtl/run_tb.sh` 가 시뮬 전에 돌린다).
- **어서션은 `KWS_ASSERT` 안에**, `$finish` 로 (`$fatal` 은 SystemVerilog).
  합격/불합격은 `run_tb.sh` 가 로그에서 판정한다.
- **치수는 `rtl/gen/<tag>/parameters.vh` 에서.** RTL 소스에 숫자 리터럴 금지.
- **MAC strobe 는 상태에서 조합으로 뽑는다.** 레지스터로 만들면 상태보다 한 사이클
  늦게 떠서, 그 사이 카운터가 움직이는 모듈(`pw`)에서 워드 정렬이 어긋난다.
  "그 사이엔 아무것도 안 바뀐다" 에 기대지 않는다 — `pw` 에서 실제로 바뀌었다.

### 클럭 엣지 — 합성 RTL 은 `posedge` 전용, TB 는 `negedge` 구동

리뷰에서 걸리기 쉬운 자리라 명시해 둔다 (2026-08-16, 사용자 확인).

**`rtl/*.v` 에 `negedge clk` 은 하나도 없다.** 있는 것은 `always @(posedge clk or
negedge rst_n)` 의 **비동기 리셋 해제 검출**뿐이고, 그건 클럭을 양쪽 엣지로 쓰는
것과 무관한 표준 관용구다. dual-edge clocking 도 half-cycle path 도 없다.

**`rtl/tb/*.v` 는 `negedge` 에서 자극을 준다. 의도적이다.**

```
   posedge        negedge        posedge
      │              │              │
  DUT 샘플      TB 가 값 변경    DUT 샘플
```

자극 변화를 샘플링 엣지에서 반 클럭 떼어 놓으면, TB 의 blocking(`=`)과 DUT 의
non-blocking(`<=`)이 같은 시각에 경쟁하지 않는다. 시뮬레이션에서 setup/hold 가
구조적으로 보장된다.

> TB 도 `posedge` 로 옮기려면 non-blocking 구동으로 바꾸고, **읽을 때 NBA 영역을
> 의식해야 한다** — posedge 직후 blocking 으로 읽으면 옛 값을 본다. `tb_dw_conv`
> 의 첫 버전이 정확히 그 계열의 착각으로 128 프레임 전부 "출력 없음" 을 보고했다.
> posedge 통일은 그 함정을 줄이지 않고 늘린다.
