# 브링업 — 보드에 처음 올리는 것

목적은 하나다. **Exp. Port 뱅크의 VCCO 가 몇 V 인가.** 이 값이 아날로그 회로를
정한다(`docs/hanback_kit.md` §4). 겸사겸사 툴체인·JTAG·클럭·핀 배정도 같이 확인된다.

---

## ⚠️ 먼저 — 빌드하는 곳과 프로그램하는 곳이 다르다

Vivado 는 원격 서버(WSL)에 깔지만 **킷은 연구실에 있다.** 비트스트림을 만드는 것과
보드에 올리는 것은 다른 기계에서 일어난다.

```
원격 WSL 서버          연구실 PC              연구실 책상
Vivado 전체    ──.bit──▶  Vivado Lab   ──JTAG──▶  XC7S75 킷
(합성·배치·비트스트림)     (프로그램만)
```

**연구실 PC 에 `Vivado Lab Edition` 이 필요하다.** 프로그래밍 전용 배포판이라
용량이 훨씬 작고 라이선스가 필요 없다. 없으면 `.bit` 를 만들어 놓고도 못 올린다.

> ⚠️ **JTAG 케이블도 확인이 필요하다.** 킷 사양표(95쪽)는 부속으로
> *Intel ByteBlaster II or Xilinx Parallel III* 를 적는데 **둘 다 병렬포트 시절
> 물건이고 요즘 Vivado 가 지원하지 않는다.** FPGA 모듈의 J5(2×7 헤더)에 꽂을
> **Platform Cable USB II** 나 **Digilent HS2/HS3** 가 따로 있어야 할 수 있다.
> 케이스 사진에 파란 USB 장치가 보였으니 그게 무엇인지 확인하면 끝난다.

### 프로그램을 못 하게 되면 — VCCO 를 얻는 다른 길 둘

1. **킷 매뉴얼의 전원부 절.** 94~99 쪽 말고 전원/뱅크를 다루는 절이 있으면
   VCCO 가 거기 적혀 있을 수 있다. **하드웨어가 필요 없는 가장 싼 길이다.**
2. **연구실의 예제 `.xdc`.** `IOSTANDARD` 한 줄이면 확정된다.

둘 중 하나로 답이 나오면 아래 측정은 확인 사살일 뿐이다.

---

## 순서

### 0. 파트 조회 — 보드도 케이블도 필요 없다

```bash
vivado -mode batch -source rtl/probe_part.tcl -nolog -nojournal
```

몇 초면 끝나고 세 가지를 답한다: `xc7s75fgga484-1` 이 설치본에 있는지,
Exp. Port 볼들의 **뱅크 번호**(갈리면 IOSTANDARD 를 나눠 줘야 한다), **B6 가
클럭 가능 핀(MRCC/SRCC)인지**. 마지막 항목이 3번 단계의 성패를 미리 알려준다.

### 1. `vcco_probe` — 클럭 없이 도는 것

```bash
vivado -mode batch -source rtl/bringup/build_bringup.tcl
```

EXT0–EXT15 를 High 로 고정하는 것이 전부다. 로직도 클럭도 리셋도 없다.
**그래서 실패하면 원인이 툴체인이나 JTAG 으로 좁혀진다** — 클럭도 타이밍도
우리 설계도 아니다.

로그 끝의 **핀 배정 확인** 표에 16 개가 매뉴얼 값(`Y21 AA22 AB21 …`)으로 찍히는지
본다. 산출물은 `out/bringup/vcco_probe.bit`.

#### 재는 법

> ⚠️ **AFE 케이블을 뽑는다.** 이 설계는 그 16 핀을 **출력으로 구동**하고 비교기도
> 푸시풀이라 출력끼리 싸운다. 킷의 직렬 33 Ω 만으로는 100 mA 가까이 흐르고
> LPV7215 는 580 nA 마이크로파워 부품이라 못 견딘다.

1. 접지 기준을 **J6 핀 49 또는 50** 에 물린다.
2. **J6 핀 3**(= ch00)에 프로브를 댄다. 박스 헤더라 핀이 벽 안에 있으니 가는
   프로브가 편하다.
3. 읽힌 전압이 **곧 VCCO** 다. 부하가 DMM(10 MΩ)뿐이라 드라이브 강하가 없고
   직렬 33 Ω 도 DC 에서는 영향이 없다.
4. 핀 4, 5, … 18 도 훑는다. **16 개가 전부 같은 값**이어야 한다.

#### 판정

| 읽힌 값 | 뜻 | 다음 |
|---|---|---|
| **~1.8 V** | LVCMOS18, `V_IH` 1.17 V | 여유 +460 mV. **변환기도 3.3 V 레일도 필요 없다** |
| **~2.5 V** | LVCMOS25, `V_IH` 1.700 V | 스펙상 −70 mV 미달이지만 실제로는 거의 돈다. 채널 하나로 실측 |
| **~3.3 V** | LVCMOS33, `V_IH` 2.000 V | 미달. `'245` 를 넣거나 비교기를 3.3 V 로 (`hanback_kit.md` §4.2) |
| **0 V 인 핀이 섞임** | 그 핀의 배선·배정 문제 | 로그의 핀 배정 표와 매뉴얼 표를 대조 |
| **전부 0 V** | 비트스트림이 안 올라갔다 | 3번으로 가지 말고 JTAG 부터 |

**여기까지가 수요일 오전의 목표다.** 아래는 여유가 있으면.

### 2. `walk_probe` — 클럭과 핀 순서

```bash
vivado -mode batch -source rtl/bringup/build_bringup.tcl -tclargs -top walk_probe
```

한 번에 한 핀씩 2 초간 High 로 흘린다. 킷의 **클럭 선택 스위치를 `F`(50 MHz)** 에
두고 올린다. 다른 자리에 두려면 `walk_probe.v` 의 `CLK_HZ` 를 고쳐 다시 합성한다.

정적 패턴으로는 핀당 1 비트뿐이라 16 개를 구별할 수 없지만 **시간축을 쓰면
구별된다** — 프로브를 한 핀에 대고 몇 번째 칸에서 올라오는지 세면 그게 채널
번호다. 한 바퀴가 32 초다.

| 보이는 것 | 뜻 |
|---|---|
| 차례로 흐른다 | 클럭도 핀 순서도 정상 |
| **ch00 만 계속 High** | 비트스트림은 올라갔고 **클럭이 안 들어온다** |
| 전부 0 V | 1번이 통과했다면 여기 올 일이 없다 |

클럭이 안 들어오면 `B6`(MAIN_CLOCK1) 이 아닐 수 있다 — `bringup.xdc` 의
`PACKAGE_PIN` 을 `M8` / `M15` / `P15` 로 바꿔 다시 합성한다. 0번 단계가
MRCC 여부를 미리 알려주므로 그것부터 본다.

## 알아낸 값을 어디에 적을 것인가

| 알아낸 것 | 적을 곳 |
|---|---|
| VCCO | `docs/hanback_kit.md` §4 — 미결 표시를 지운다 |
| `IOSTANDARD` | `rtl/constraints/kws_top.xdc` 의 `set IOSTD` |
| 뱅크 번호 | `docs/hanback_kit.md` §2.2 |
| 클럭 핀·주파수 | `kws_top.xdc` 의 `create_clock` 과 `FRAME_CYCLES` |
| 속도 등급 | 매뉴얼이 `-1` 로 확정했다. 목록과 어긋나면 그때 고친다 |

## 이 디렉터리

| 파일 | 무엇 |
|---|---|
| `vcco_probe.v` | 16 핀 High 고정. 클럭 없음 |
| `walk_probe.v` | 한 핀씩 2 초 순회. 클럭 필요 |
| `bringup.xdc` | 둘 공용. 핀은 `kws_top.xdc` 와 **같은 값** |
| `build_bringup.tcl` | 합성→배치배선→비트스트림. 본 설계와 분리 |

본 설계(`rtl/build.tcl`)와 따로 둔 이유는, 저쪽이 `.hex` 가중치를 싣고 태그를
고르고 ROM 경로를 다시 쓰기 때문이다. 여기서 확인하려는 것은 그 어느 것도 아니고,
실패했을 때 원인이 섞이면 안 된다.
