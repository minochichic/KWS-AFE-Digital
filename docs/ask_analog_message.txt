안녕하세요. 디지털 쪽 진행 상황 공유드리고 부탁 하나 드립니다.


[ 현재 상태 ]

FPGA에 올릴 신경망 부분은 검증까지 끝났습니다. 비교기 16채널 출력만
들어오면 키워드 12개 중 하나로 분류하는 것까지 동작합니다.
(Google Speech Commands 데이터셋 기준 정확도 84.5%)

이제 남은 질문은 하나입니다 — 저희가 소프트웨어로 흉내낸 AFE가
실제 회로와 얼마나 같은가. 그건 실제 회로 출력을 봐야만 알 수 있습니다.


[ 부탁 ]

시뮬레이션에서 나온 비교기 16채널 출력을, 한 클립만 주실 수 있을까요?


[ 형식은 편하신 대로 ]

CSV, VCD, ngspice raw, 채널별 파일 — 전부 저희가 변환합니다.
필요한 정보는 딱 하나입니다:

    각 채널이 언제 1이 되고 언제 0이 되었는지

균일 샘플링이라 파일이 크면(수백만 줄) 그대로 주셔도 되고, 값이 바뀐
순간만 뽑아주시면 수천 줄로 줄어듭니다. 둘 다 괜찮습니다.

예를 들면 이런 식입니다:

    channel,time_s,value
    0,0.001234,1
    0,0.001901,0
    3,0.002011,1


[ 딱 한 가지 부탁 — 10 ms 단위로 묶지 말아주세요 ]

저희 하드웨어는 "10 ms 안에 한 번이라도 1이었으면 1"이라는 규칙으로
묶습니다. 그런데 묶는 방법이 여러 가지입니다 — 칸 끝의 값을 쓸 수도,
평균을 낼 수도, 절반 이상인지 볼 수도 있죠.

규칙이 다르면 같은 신호에서 정반대 결과가 나옵니다. 실제로 저희가
30 ms 구간 하나로 계산해보니 저희 규칙은 111, 다른 세 규칙은 000이
나왔습니다.

문제는 결과만 봐서는 어느 규칙으로 묶은 건지 알 수가 없다는 겁니다.
넷 다 그럴듯한 0/1 패턴이라, 나중에 정확도가 이상해도 원인을 못 찾습니다.

그래서 묶기 전 것을 주시면 묶는 건 저희가 하겠습니다.

  * 이미 묶어놓으신 게 있다면: 그 클립의 묶기 전 원본도 한 번만 같이
    주세요. 저희 규칙으로 묶어서 대조해보고 일치하면, 그 뒤로는 묶은
    것만 주셔도 됩니다.


[ 같이 알려주셔야 할 4가지 ]

이게 없으면 어긋나도 증상으로 못 찾습니다.

  1. 오디오가 시작되는 시각
     시뮬 앞에 정착 구간이 있으면 그만큼 프레임이 밀립니다.

  2. 채널 번호 순서
     저희는 0번이 최저 주파수(166 Hz), 15번이 최고(6761 Hz)입니다.
     반대로 매기셨으면 알려주세요.

  3. 극성
     값 1이 "엔벨로프가 임계값보다 위"인가요, 아래인가요.

  4. 어느 wav 파일로 돌리신 건지
     같은 오디오로 저희 시뮬레이션도 돌려서 비트 단위로 비교하려는
     거라 이게 꼭 필요합니다. 정답 레이블은 저희가 압니다.

4번은 저장소의 analog/AFE/audio/ 에 있는 클립 중 아무거나 하나
고르시면 제일 편합니다 (go.wav, no.wav, yes.wav, up.wav, down.wav ...).


[ 한 클립이면 충분합니다 ]

여러 개 돌리실 필요 없습니다.

트레이스 몇 개로 "정확도"가 나오지는 않습니다 (그건 수백 클립이
필요한데 SPICE로는 현실적이지 않죠). 대신 나오는 건 "저희 소프트웨어
시뮬이 실제 회로를 얼마나 잘 흉내내고 있나"이고, 그건 한 클립의
비트 단위 비교로 충분히 답이 나옵니다.

그 결과에 따라 다음이 정해집니다:

  거의 일치        →  그대로 진행. 정확도도 유지될 겁니다
  몇 채널만 어긋남  →  그 채널의 임계값이나 중심주파수를 확인
  많이 다름        →  회로에 맞춰 신경망을 다시 학습합니다

마지막 경우여도 다시 학습하는 건 저희 쪽이고, FPGA 코드는 그대로입니다.
그래서 부담 갖지 않으셔도 됩니다.


감사합니다.
