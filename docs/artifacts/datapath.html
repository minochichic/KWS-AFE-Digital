.xdc 와 .tcl 이 어디에 붙는가

위 다이어그램에서 왼쪽 점선 바깥이 제약 파일의 관할이다. 안쪽 로직은 Verilog 가 정하고, 바깥으로 나가는 신호의 전기적 성질과 타이밍은 .xdc 가 정한다.

X

kws_top.xdc — 세 줄이 전부 다른 문제를 푼다

create_clock 은 얼마나 빨라야 하는가. Verilog 어디에도 이 숫자가 없다.

set_false_path -from [get_ports {cmp[*]}] 은 분석하지 말라. 비교기는 우리 클럭과 무관하게 흔들리므로 첫 플립플롭은 정의상 셋업/홀드를 만족할 수 없다. 안 빼면 도구가 없는 경로를 맞추려다 로직을 비튼다.

ASYNC_REG TRUE 는 두 FF 를 붙여 놓아라. 같은 슬라이스에 두면 메타스테이빌리티가 가라앉을 시간이 길어진다.

1

build.tcl — .hex 를 run 디렉터리로 옮긴다

Icarus 는 리포 루트에서 돌아 rtl/gen/…/x.hex 를 찾지만, Vivado 는 합성 run 디렉터리에서 찾아 하나도 못 찾는다. 그런데 에러가 아니다 — ROM 이 X 로 남고 합성은 성공한다.

.hex 35 개 → out/synth/<part>/inc/ paths.vh 를 파일명만 남긴 사본으로 재작성
2

kws_top_synth.v — ROM 경로를 꽂는다

kws_top 의 경로 파라미터는 기본값이 "" 이고 RTL 이 그걸 걸러낸다. 그냥 합성하면 가중치가 하나도 없는 회로가 조용히 나온다. 래퍼가 테스트벤치와 같은 매크로 35 개를 꽂는다.

3

synth_design → 리포트

Verilog 가 LUT · FF · BRAM 으로 바뀐다. -flatten_hierarchy none 이라 모듈별로 나온다.

report_utilization -hierarchical report_timing_summary == BRAM 셀 N 개 == ← 0 이면 1 단계가 실패한 것

아날로그와 디지털은 대화하지 않는다

"통신을 어떻게 하는가"가 감이 안 잡히는 이유는, 통신이 없기 때문이다. 버스도 핸드셰이크도 패킷도 없고, FPGA 가 아날로그로 보내는 신호는 한 가닥도 없다. 16가닥이 각각 높거나 낮은 전압을 계속 유지할 뿐이고, FPGA 는 그냥 쳐다본다.

경계를 넘는 것

  • 전압 규약0–1.8 V 스윙 → LVCMOS18. VADJ 를 1.8 V 로 내려 맞춘다
  • 극성 규약cmp[k]=1 ⟺ ch k 에 에너지 있음 (ICD §3)
  • 가닥 ↔ ch 매핑동료의 배선. 아직 안 왔다

넘지 않는 것

  • 클럭공유하지 않는다. 아날로그는 프레임이 뭔지 모른다
  • FPGA → 아날로그 신호없음. 아날로그는 자유 구동 (ICD §2)
  • 아날로그 파라미터f_c · Q · τ · 임계값 · 이득 — 전부 비교기 왼쪽에서 소진

시간축이 공유되지 않는다는 게 핵심이다. 프레임 경계는 FPGA 가 자기 클럭으로 혼자 정한다. 그래도 되는 이유는 축약 규칙이 "언제 울렸나"가 아니라 "한 번이라도 울렸나"라서다 — 아래에서 격자 위상을 밀어 보면 결과가 거의 그대로인 것이 보인다. 만약 샘플 타이밍이 필요했다면 클럭을 공유해야 했고, 그러면 아날로그 기판 위로 디지털 클럭이 올라갔을 것이다.

연구실 실습시간 최소화

연구실에서만 할 수 있는 일은 파트 라이선스가 필요한 합성과 보드에 굽기 둘뿐이다. 나머지는 전부 여기서 끝낼 수 있고, 끝내 두면 거기서는 리포트만 읽으면 된다.

여기서 끝낼 것

GPU 박스 · Vivado 불필요
  1. Verilator 린트 -Wall폭 truncation, 의도 안 한 래치. 설치 0분
  2. yosys 합성 한 번합성 불가 구문과 $readmemh 로드 여부. apt 1분
  3. 임계값 확정 → 동료 SPICE → 재학습가중치가 정해져야 .hex 가 정해진다
  4. export 재실행최종 태그로 .hex · paths.vh · 골든 벡터 생성
  5. Icarus 12개 테스트벤치 재통과새 가중치로도 골든 벡터가 맞는지
  6. VADJ 뱅크 용도 확인1.8 V 로 내리면 뱅크 12/13/16/17/18 이 같이 내려간다. 우리가 쓰는 게 없는지 (bank 12 = SDIO). 문서만 보면 된다
  7. 동료에게 핀 ↔ ch 매핑 요청UG810 은 FMC 핀 ↔ FPGA 핀만 답한다. ch 번호는 배선이라 문서로 받아야 한다
→ 연구실 도착 시점에 남는 것: 파트 하나 + 전원 설정

연구실에서 할 것

Vivado Enterprise · 보드 · TI Fusion
  1. J65 점퍼 제거 → UCD9248 을 1.8 V 로TI Fusion Digital Power Designer GUI. FPGA 를 PMBus 마스터로 만드는 쪽은 피한다
  2. VADJ 실측FMC 커넥터에서 1.8 V 가 나오는지. 여기가 아니면 뒤가 전부 헛수고다
  3. build.tcl 한 줄파트만 XC7K325T 로. 첫 실행은 문법 조정이 있을 수 있다
  4. 로그 세 줄 확인BRAM 셀 개수 · Critical Warning · WNS
  5. 핀 배치 작성 → -impl매핑이 온 뒤. .xdc 2 절만
  6. 아날로그 없이 먼저 굽기tb_top 벡터를 내부에서 먹여 같은 클래스가 나오는지. 여기까지 아날로그는 안 꽂는다
  7. 그 다음에 16가닥 연결브레이크아웃 카드 → 케이블. 채널 하나씩 두드려 매핑 검증
→ 1~2 가 깨끗하면 나머지는 절차다
가장 크게 시간을 아끼는 것은 순서다. 가중치가 확정되기 전에 합성하면 .hex 가 바뀔 때 전부 다시 해야 한다. 반대로 RTL 구조 문제는 가중치와 무관하므로 지금 yosys 로 털어낼 수 있다 — 그 둘을 분리하면 연구실에서 build.tcl 한 번으로 끝난다.

브링업도 같은 이유로 순서가 있다. 모르는 쪽을 한 번에 하나씩만 늘린다 — 아날로그를 꽂기 전에 FPGA 가 골든 벡터를 통과하는 것을 먼저 보고, 그 다음에 16가닥을 붙인다. 둘을 같이 켜면 틀렸을 때 어느 쪽인지 알 방법이 없고, 핀 매핑이 섞인 경우는 증상이 "정확도가 좀 낮다"뿐이라 특히 그렇다.
