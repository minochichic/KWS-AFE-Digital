KWS-AFE-Digital · RTL 12/12 검증 · P5-g 대기

마이크에서 클래스 인덱스까지

아날로그 필터뱅크 16채널이 만든 이진 이미지가 FPGA 안에서 12개 클래스 중 하나가 되기까지. 각 단을 눌러 무엇을 하는지, 무엇이 그 경계를 넘는지 확인한다.

정확도 0.825 (bd_base) 입력 16 × 128 이진 파라미터 106,240 KC705 점유 ~1.3%

신호 사슬

구리색은 아날로그(동료 담당), 청록색은 디지털(우리 담당)이다. 둘 사이의 점선이 docs/ICD.md 가 정의하는 경계이고, 그 위를 넘는 것은 비교기 16가닥과 프레임 타이밍뿐이다.

연구실 가기 전에 만든 것

RTL 은 Icarus 로 12개 모듈 전부 골든 벡터 검증을 마쳤다. 남은 것은 합성이고, Vivado 는 Icarus 가 봐주던 것들을 봐주지 않는다. 아래 셋이 그 간극을 메운다.

제약

rtl/constraints/kws_top.xdc

클럭 주기, 비동기 입력의 false path, 동기화기의 ASYNC_REG. 파트와 무관한 절반이다.

핀 배치는 비워뒀다 — 파트와 비교기 전압 레벨(ICD §7)이 정해져야 쓸 수 있고, 합성만 할 거면 없어도 된다.

빌드

rtl/build.tcl

GUI 없이 한 줄로 합성하고 utilization·타이밍 리포트를 남긴다. 파트는 인자다.

GUI 로 하면 누가 뭘 눌렀는지 기록이 안 남아 결과가 재현되지 않는다.

래퍼

rtl/synth/kws_top_synth.v

테스트벤치와 같은 매크로로 ROM 경로 35개를 꽂아준다. 파라미터 블록은 tb_top.v 에서 기계적으로 추출했다.

베껴 쓰면 언젠가 어긋나고, 어긋나도 합성은 성공한다. 테스트가 둘을 대조한다.

왜 래퍼가 필요한가 — 두 번 다 조용히 실패한다

Vivado 로 넘어갈 때 실제로 깨지는 건 Verilog 가 아니라 파일 경로다. 그리고 둘 다 에러를 내지 않는다. 합성은 성공하고, 가중치만 없다.

Icarus (지금)
run_tb.sh 가 리포 루트로 cd
$readmemh("rtl/gen/xl_g12/conv1_w.hex")
  → 찾음. ROM 채워짐.
✓ 가중치 실림
Vivado (고치기 전)
cwd = project.runs/synth_1/
$readmemh("rtl/gen/xl_g12/conv1_w.hex")
  → 없음. 경고조차 없음.
  → ROM 은 X 로 남음.
✗ 가중치 없는 회로가 합성 성공

build.tcl 이 .hex 를 run 디렉터리로 복사하고 paths.vh 를 파일명만 남긴 사본으로 바꾼다. 그리고 합성 뒤 BRAM 이 실제로 추론됐는지 세어 로그에 남긴다 — 0 이면 다시 그 함정에 빠진 것이다.

Vivado 세 단계

GUI 왼쪽 Flow Navigator 의 버튼 순서와 같다. 지금 준비된 건 첫 단계까지다.

단계하는 일산출물지금
SynthesisVerilog → LUT / FF / BRAM / DSPutilization 리포트준비됨
Implementation게이트를 칩의 실제 위치에 배치·배선timing 리포트핀 제약 필요
Bitstream배선 결과 → .bit보드에 쓸 파일파트 확정 필요

라이선스: XC7K325T 는 무료 Vivado ML Standard 대상이 아니다(Enterprise 필요). 다만 프로젝트 파일은 에디션과 무관하므로, 무료 파트로 먼저 합성해 RTL 문제를 털어낸 뒤 연구실에서 파트만 바꿔 다시 돌리면 된다.
