# v4 전송본 요청 (2026-08-28)

v3 로 10클래스 학습해서 **0.723~0.730** 이 나왔습니다. 우리 소프트웨어 시뮬은
12클래스로 0.825 인데, **두 숫자를 비교할 수가 없습니다** — 세 가지가 동시에
다르기 때문입니다:

| | 우리 시뮬 (`bd_base`) | v3 전송본 |
|---|---|---|
| 클래스 | 12 (`_silence_`, `_unknown_` 포함) | **10** |
| 시간 정렬 | 클립 t=0, 단어가 대체로 가운데 | **첫 이벤트 트리거, 앞으로 몰림** |
| 검출기·비교기 | 이상화 (sqrt 근사, 오프셋 0) | **실제 회로 (PCHIP, 실제 임계값)** |

우리가 정말 알고 싶은 건 **세 번째 줄** 입니다 — "우리 시뮬이 실제 회로와 얼마나
다른가". 그런데 지금은 그게 앞의 둘에 가려 안 보입니다.

---

## 1. 클립 원래 타이밍 버전 (가장 중요)

v3 는 `trigger: "first sample where any channel v_env >= vthr"` 로 첫 비교기
이벤트에 정렬합니다. **이건 wake-up 하드웨어에 충실한 설계이고 잘못이 아닙니다.**
다만 그것 때문에 정보가 앞 30프레임에 몰립니다 — 저희가 측정한 값입니다:

| 구간 | 선형 프로브 정확도 |
|---|---:|
| 전체 0-99 | 0.577 |
| **앞 0-29 만** | **0.567** |
| 뒤 40-99 | 0.136 (랜덤 0.10) |

프레임 60 이면 클립의 **96% 가 완전히 비어** 있습니다.

**요청**: 트리거 없이 **클립 t=0 에서 시작해 100 bin(1초)** 을 그대로 뜬 버전.

### "1초 넘는 것"에 대해

말씀하신 대로 회로 응답은 1초를 넘습니다 (C3 τ 가 최대 21.5 ms 라 단어가 끝난
뒤에도 v_env 가 감쇠하며 이어짐). **그건 그냥 자르시면 됩니다.**

저희 파이프라인이 이미 그렇게 합니다 — 원본 wav 를 `wave[:16000]` 으로 앞 1초만
쓰고, 짧으면 뒤를 0 으로 채웁니다. **1초 뒤의 꼬리는 저희 시뮬도 본 적이 없으므로**
버리는 게 손실이 아니라 오히려 **일치**입니다.

즉 규칙은 단순합니다:

- 시작 = 클립 t=0 (트리거 없음)
- 길이 = 100 bin 고정
- 100 bin 을 넘는 응답 = 버림
- 100 bin 이 안 되면 = 0 으로 채움

(참고로 Speech Commands v2 의 단어 wav 자체는 1초 이하입니다. 1초를 넘는 건
`_background_noise_` 뿐인데 그건 아래 2번에서 잘라 쓰는 용도입니다.)

## 2. `_silence_` 와 `_unknown_`

저희 과제는 12클래스입니다. v3 에는 키워드 10개뿐이라 나머지 둘이 없습니다.

| 클래스 | 만드는 법 | 저희 12클래스에서의 성적 |
|---|---|---|
| `_silence_` | `_background_noise_` 의 6개 파일에서 **1초씩 잘라내기** | 0.993 (최고) |
| `_unknown_` | 키워드 10개를 뺀 **나머지 25개 단어**에서 일부 | 0.644 (최악) |

이 둘이 정확히 저희 최고·최악 클래스라, 빼고 재면 숫자가 어느 쪽으로 움직일지
계산이 안 됩니다. **12클래스로 맞춰야 비교가 됩니다.**

개수는 키워드 한 클래스 분량이면 충분합니다 (각 ~3,800). `_unknown_` 은 25개
단어에서 고르게 뽑으시면 됩니다.

## 3. draft → 검증본

`export_settings.json` 에 도구 자신의 경고가 있습니다:

```
"status": "draft"
"draft package: 일부 채널 또는 Vthr band의 일치가 보장되지 않습니다."
"보장 Vthr band 없음: ch00, ch01, ..., ch15"      ← 16채널 전부
```

가능하면 검증된 패키지로 부탁드립니다. 임계값이 임의값인 것과는 별개로, 도구가
**어느 채널도 보장 못 한다**고 말하고 있어서 숫자를 어디까지 믿을지 판단이 안
섭니다.

## 우선순위

**1번 하나만 있어도 큰 진전**입니다. 시간 정렬 변수가 지워지면 남는 게 클래스
수 차이(계산으로 보정 가능)와 회로 차이뿐이라, "시뮬 vs 실물" 이 처음으로
숫자로 나옵니다.

2번까지 오면 완전히 같은 축이 되고, 3번은 그다음입니다.

## 참고: v3 에서 저희가 찾은 것들

받은 데이터 자체는 **정상**입니다. 죽은 채널 0개, 포화 0개, 발화율 4~24%.
아래는 저희가 맞춰야 했던 것들이라 공유합니다.

- **`row_order` 가 역순**입니다 (`[ch15 ... ch00]`, CSV 행 0 = 최고역). 매니페스트에
  적혀 있어서 읽어서 처리했습니다. 의도하신 거면 그대로 두셔도 됩니다.
- 채널 총 비트 **9.05 / 16** (저희 시뮬은 11.16).
- 저희가 SPICE 로 잰 "고역 스윙이 약하다"와 데이터가 일치합니다 — 되돌린 순서로
  ch0(최저역) 10%, ch15(최고역) 2% 발화.
