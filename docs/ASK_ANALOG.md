# 아날로그 쪽에 요청할 것

**요약**: 시뮬레이션 파형 **한 클립**과, 그게 어느 wav 인지. 그게 전부다.
나머지는 그 결과를 보고 정한다.

---

## 1. 지금 어디까지 되어 있나

디지털 쪽은 **끝났다.** 비교기 16가닥이 들어가면 클래스 인덱스가 나온다
(`docs/WHITEPAPER.md`). 12개 모듈, 12,004개 값이 골든 벡터와 일치.

지금 돌아가는 입력은 **GSC 오디오를 우리가 소프트웨어로 시뮬한 AFE** 출력이다.
STFT → 16채널 Mel → envelope → 채널별 학습 threshold → ±1. 실물 회로가 아니다.

---

## 2. 질문을 둘로 나눠야 한다

### Q1. 동료 데이터를 우리 Verilog 에 넣고 돌릴 수 있나 → **그렇다**

경계를 넘는 건 **비교기 16가닥과 프레임 타이밍뿐**이다. 파형만 있으면
`experiments/trace_to_frames.py` 가 프레임으로 바꾸고, 그대로 RTL 에 들어간다.

### Q2. 그 결과 나오는 클래스가 **맞을 것인가** → **모른다. 그게 진짜 질문이다**

가중치는 **우리 소프트웨어 AFE 로 학습됐다.** 실물 회로의 envelope·threshold
거동이 우리 시뮬과 다르면 ±1 패턴이 달라지고, 학습된 가중치는 그 패턴을
설명하지 못한다.

**그때 나오는 건 에러가 아니라 자신만만한 오답이다.** 그래서:

> 동료 데이터로 **제일 먼저 할 일은 분류가 아니라 대조**다.
> 같은 오디오에 대해 **우리 시뮬 vs 그쪽 회로**의 비교기 출력을 비트 단위로 비교한다.

그 불일치율이 이후 계획을 정한다:

| 불일치 | 뜻 | 다음 |
|---|---|---|
| ~0% | 우리 시뮬이 회로를 잘 맞췄다 | 그대로 분류. 정확도도 유지될 것 |
| 몇 % | 대체로 맞고 채널 몇 개가 어긋남 | 어긋난 채널만 조사 (threshold? f_c?) |
| 10% 이상 | 다른 프론트엔드다 | **회로에 맞춰 재학습** (Phase B). RTL 은 안 바뀐다 |

마지막 줄이 핵심이다. **최악의 경우에도 고치는 건 가중치이지 RTL 이 아니다**
(`docs/ICD.md` §6).

## 3. 최소 요청 — 이거 하나면 시작한다

### (1) 비교기 16채널 파형, 한 클립

**형식**: CSV, **전이(transition)마다 한 줄**. 샘플마다가 아니라.

```csv
channel,time_s,value
0,0.001234,1
0,0.001901,0
3,0.002011,1
```

- `channel` — 0..15
- `time_s` — 초. 상대 시간이어도 되고, `t0` 는 우리가 지정할 수 있다
- `value` — 0 또는 1. 첫 줄 이전에는 0으로 가정한다

전이 기준이면 1초 음성이 **수천 줄**이다. 균일 샘플링은 수백만 줄이 된다.

> 다른 포맷(VCD, 채널별 파일, 균일 샘플)도 상관없다. 변환은 우리가 한다 —
> **위 형식은 "이게 정확히 필요한 정보"라는 뜻**이지 이 확장자여야 한다는 뜻이 아니다.

### (2) 그 파형을 만든 **wav 파일** (또는 GSC 안에서의 경로)

**이게 (1)만큼 중요하다.** 같은 오디오로 우리 시뮬을 돌려야 대조가 된다.
아무 클립이나 하나 골라서 알려주면 된다 — 정답 레이블은 우리가 안다.

### (3) 채널 순서

`channel 0` 이 **최저 주파수**인가 최고인가. 우리 쪽은 0 = 166 Hz, 15 = 6761 Hz.
(섞이면 증상으로 못 찾는다.)

### (4) 극성

`value=1` 이 **"envelope 이 threshold 위"** 인가 아래인가.
반전이면 파라미터(`CMP_INVERT`) 하나로 흡수한다. 재설계 아니다.

---

## 4. 받으면 우리가 하는 것

```bash
# 프레임으로 바꾸고, 같은 오디오에 대한 우리 시뮬과 대조
python -m experiments.trace_to_frames --trace cmp.csv \
       --compare runs/xl_g12 --wav <그 wav>

# 그대로 RTL 에 넣어 클래스까지
python -m experiments.trace_to_frames --trace cmp.csv --out cmp_input.hex
./rtl/run_tb.sh top
```

첫 명령이 채널별 불일치 비트 수를 찍는다. **한 채널만 유난히 나쁘면** 그 채널의
threshold 나 중심주파수가 움직인 것이지 프론트엔드 전체가 틀린 게 아니다.

## 6. 자료가 아예 없어도 되는 것

**GSC 만으로 분류는 이미 된다.** 지금 `tb_top` 이 하는 게 그거다.

- **정확도** (float 모델, 전체 테스트셋): `xl_g12` = **0.8445**
- **정수 경로 정확도** (RTL 이 실제로 계산하는 것): `experiments/fixed_accuracy.py`
  로 측정. 이진 층은 **정확(exact)** 해서 차이는 전부 꼬리의 고정소수점이다

동료 자료 없이도 할 수 있는 것:
1. 정수 경로의 전체 테스트셋 정확도 (위 스크립트)
2. Vivado 합성 — 점유율·타이밍·BRAM/DSP 추론
3. 트랙 2(고정 임계값) 재학습

**동료 자료가 있어야만 답할 수 있는 건 하나뿐이다**: 우리 소프트웨어 AFE 가
실물 회로를 얼마나 잘 흉내내고 있나.
