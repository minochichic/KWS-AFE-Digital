# 아날로그 쪽에 요청할 것

**요약: 파일 하나다.** 채널별로 **실제로 살 부품의 값과 공차**를 적은 BOM.
비교기 파형도, 추가 시뮬도 지금은 필요 없다 — 우리가 직접 돌릴 수 있다.

---

## 1. 이미 가진 것 (다시 안 받아도 되는 것)

동료가 준 **회로**(`analog/ngspice_v15_2608001/`, 벤더 모델 포함)로 우리가 직접
ngspice 를 돌려서 아래를 전부 추출해 뒀다. 데이터를 받는 관계가 아니라
**회로를 받아 우리가 시뮬하는 관계**다.

| 항목 | 값 | 출처 |
|---|---|---|
| 16채널 필터뱅크 응답 | `filterbank_matrix.csv` — **학습이 매 런 읽는다** | `AFE/artifacts/` |
| f_c 설계 정확도 | 평균 0.9%, 최대 2.0% | `AFE/README.md` |
| GIC 통과대역 이득 | 2.00 (6 dB) | `AFE_tuning/` |
| 검출기 이득 G = R5/R4 | 4.7 | 회로 |
| **엔벨로프 시상수 τ = R5·C3** | **4.7 ms** | 회로 |
| 검출기 정지점 v_env | 917.8 mV (동료 917.83 과 0.55 mV 일치) | `r7r8_real.md` |
| R7/R8 채널별 | 확정 | `r7r8_per_channel.md` |
| op-amp GBW | OPA379 92 kHz / TLV9042 328 kHz / TLV9041D 1.72 MHz | `opamp_gain_per_channel.md` |

**그래서 "비교기 파형을 달라"는 옛날 요청이다.** 필요하면 우리가 만든다.

---

## 2. 진짜 빠진 것 — 부품이 실재하지 않는다

`analog/AFE/artifacts/component_table.md` 첫 줄이 그대로 말하고 있다:

> 연속(continuous) 설계값. **E12/E24 스냅·공차는 제작 단계에서 반영.**

그 표의 커패시터는 `76.56 / 42.35 / 27.93 / … / 1.86 nF` 다. **이런 부품은 없다.**
그런데 `filterbank_matrix.csv` 는 이 값들로 만들어졌고, 학습이 그걸 읽는다.
**지금 우리가 학습하는 필터뱅크는 살 수 없는 부품의 필터뱅크다.**

그리고 **제작 단계가 바로 지금**이다.

### 2.1 스냅은 고칠 수 있다

C 를 E24 로 스냅하고 RA 를 그대로 두면 f_c 가 최대 4.8% 어긋난다(E12 는 8.9%).
하지만 **RA 와 R1 을 다시 풀면 대부분 회수된다** — `RA → f_c`, `R1 → Q` 가 분리돼
있고(`AFE/README.md`) 저항은 E96(1%)까지 촘촘하다. 이건 우리가 할 수 있는 일이다.

### 2.2 공차는 못 고친다 — 이게 요청의 이유다

부품을 아무리 잘 골라도 공차는 남는다. `f_c ∝ 1/(RA·C)` 이므로:

- 저항 ±1% → 무시 가능
- **커패시터가 지배한다.** ±10% 면 f_c 가 약 ±10%

우리 채널은 Q 가 1.3~6.5 로 **좁다.** f_c 가 ±10% 흔들리면 그게 **그 채널 대역폭의
몇 %인지**가 진짜 질문이다:

| 채널 | f_c | 대역폭 | ±10% 가 대역폭의 |
|---:|---:|---:|---:|
| 0 | 166 Hz | 125 Hz | 13% |
| 7 | 1660 Hz | 340 Hz | 49% |
| 15 | 6761 Hz | 1048 Hz | **65%** |

**상위 채널은 자기 대역폭의 3분의 2만큼 밀릴 수 있다.** 우리 설계 오차 0.9% 를
한 자릿수 넘어선다. 우리는 1% 수준을 다듬어 왔는데 그 아래에 모델링 안 된 10% 가
깔려 있는 셈이다.

### 2.3 그래서 진짜 묻고 싶은 건 유전체다

| 유전체 | 공차 | 온도 드리프트 | f_c 총 이동 |
|---|---|---|---|
| **C0G / NP0** | ±2~5% | ±0.3% | **±3~5%** — 괜찮다 |
| X7R | ±10% | ±15% | ±25% + DC 바이어스 — **대역폭 1.5배**. 위험 |

**C0G 면 문제 없고, X7R 이면 다시 설계해야 한다.** 이 한 줄이 제일 중요하다.

> ⚠️ 다만 저주파 채널은 C 가 크다(ch0 = 76.6 nF). 그 용량대의 C0G 는 부품이 크고
> 비싸다 — **저주파 채널만 C 를 줄이고 RA 를 키우는 재배치**가 필요할 수 있다.
> 그건 우리가 다시 풀 수 있다. **어느 쪽이 곤란한지 알려주는 게 동료의 몫이다.**

## 3. 요청 — 파일 하나

`bom.csv`. 채널마다 한 줄, **실제로 살 부품**.

```csv
ch,part,value,unit,tolerance_pct,dielectric,mpn,note
0,RA,12.4,kohm,1,,RC0603FR-0712K4L,E96
0,C,75,nF,5,C0G,,병렬 2개
0,R1,16.5,kohm,1,,,
...
```

| 컬럼 | 왜 필요한가 |
|---|---|
| `ch` | 0..15 |
| `part` | `RA` `C` `R1` `R2` `R4` `R5` `R6` `C3` `R7` `R8` |
| `value`, `unit` | **연속 설계값이 아니라 실제 부품값** |
| `tolerance_pct` | 이게 없으면 f_c 가 어디까지 밀리는지 계산이 안 된다 |
| `dielectric` | **커패시터만. C0G/NP0 인지 X7R 인지 — 제일 중요한 한 칸** |
| `mpn` | 있으면 좋음(데이터시트로 온도 특성 확인 가능). 없어도 됨 |
| `note` | 병렬/직렬 조합, 구하기 어려운 값 등 |

**형식은 아무래도 좋다** — 엑셀이든 표든 메신저로 적어주든 상관없다. 위 표는
"이 정보가 필요하다"는 뜻이지 이 확장자여야 한다는 뜻이 아니다.

### 부품이 아직 안 정해졌다면

그게 더 흔한 경우다. 그러면 **반대로 우리가 제안서를 만들어 보낸다**:
C 를 E24 로 스냅하고 RA·R1 을 다시 풀어서 f_c 오차를 최소화한 표. 동료는
**구할 수 있는지만 확인**하면 된다. (다만 CLAUDE.md §5 가 E-계열 작업을 제작
단계로 미뤄 뒀으므로, 이건 시작 전에 승인을 받는다.)

### 같이 물어볼 한 줄짜리 두 개

1. **커패시터를 C0G 로 가는 게 가능한가?** 특히 저주파 채널(수십 nF).
   안 되면 어느 채널부터 곤란한지.
2. **보드가 이미 있나, 아니면 아직 설계 중인가?** 있으면 실측이 시뮬을 이긴다.

## 4. 받으면 우리가 하는 것

1. 실제 부품값으로 ngspice 재실행 → **`filterbank_matrix.csv` 재생성**
2. 공차 몬테카를로 — f_c 가 최악으로 밀린 필터뱅크에서 정확도가 얼마나 떨어지나.
   **이 숫자가 "±5% 부품을 살 가치가 있는가"에 답한다**
3. 필요하면 그 필터뱅크로 재학습 (**RTL 은 안 바뀐다** — `docs/ICD.md` §6)

---

## 5. 지금은 필요 없는 것

- **비교기 전 구간 파형** — 필요하면 우리가 돌린다. 형식만 정해 두면 되고
  (`experiments/trace_to_frames.py` 가 그 CSV 를 먹는다), 실물 보드가 생겼을 때
  **실측 대 시뮬** 대조용으로 의미가 생긴다
- **물리 인터페이스 7가지** (`docs/ICD.md` §7) — 출력 전압 레벨, 푸시풀/오픈드레인,
  커넥터, 핀↔채널 매핑, 케이블 길이, 전원 독립, 극성. 보드를 FPGA 에 물릴 때
