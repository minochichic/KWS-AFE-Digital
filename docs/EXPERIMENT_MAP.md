# 각 실험이 무엇을 정하나 — 하드웨어 / 소프트웨어

모든 손잡이는 셋 중 하나다:

| | |
|---|---|
| **A. 회로** | 동료가 **납땜할** 값을 정한다. 틀리면 보드를 다시 만든다 |
| **B. FPGA** | RTL 구조·타이밍을 정한다. 틀리면 다시 합성한다 |
| **C. 학습만** | 하드웨어에 **흔적이 없다**. 언제든 다시 학습하면 된다 |

**이 구분을 놓친 게 지금까지 가장 비쌌다.** §5에 네 번의 사례를 적어 뒀다.

## 한눈에

| 손잡이 | 소프트웨어에서 | 하드웨어에서 | 분류 | 상태 |
|---|---|---|---|---|
| `n_channels` | mel 필터 수 | **GIC 필터·검출기·비교기 개수 = 전력** | A | ✅ 16 |
| `f_min` / `f_max` | 필터뱅크 범위 | **각 GIC 의 R·C 값** | A | ✅ 50–8000 Hz |

| `lse_temp_frac` | soft max 의 부드러움 | **요구 엔벨로프 스윙 → 프리앰프 이득** | A | ⚠️ 0.78 철회, 평탄대 13–50 mV |
| `xmax_floor_frac` → **δ** | 무음 squelch | **V_ref 오프셋 = 저항 2개** | A | ⚠️ §6e 진행 중 |
| `comparators_per_channel` | 입력 행 수 (비트) | **비교기 개수 = +17 µW/개** | A | ✅ 1 (2는 업그레이드) |
| `spice_gain_restore` | 채널간 절대 스케일 | **채널 이득을 맞춰야 하나** | A | ⬜ 미시험 |
| `comparator_vos` | 임계에 더하는 오차 | **비교기 부품 선택** | A | ⏸ **보드 만든 뒤 측정** |
| `envelope_win_ms` / `T` | 프레임 격자 | **FPGA 프레임 타이머 + 시프트 레지스터 깊이** | B | ✅ 10 ms / 128 |
| 창 위치 곡선 | 위치 강건성 | **FPGA 판정 규칙 (최대확신도 + 불응기)** | B | ✅ 1.8pp |
| 모델 크기 | 파라미터 | **MAC 엔진 접는 정도, BRAM** | B | ✅ 96.5K |
| `aug_gain_db` | 음량 강건성 | **없음** (단, 스윙 스펙을 얼마나 조여야 하는지를 바꾼다) | C | ⬅️ 다음 |
| `aug_time_shift_ms` | 시간 이동 강건성 | 없음 | C | ❌ 실패, 종료 |
| `aug_noise_prob` | 배경잡음 강건성 | 없음 | C | ⬜ 우선순위 상승 |
| `seed` | 초기화·셔플 | 없음 | C | ⚠️ **test 세트도 바꾼다** (§4) |
| `binarize` | 비교기 우회 | **없음 — 하드웨어 옵션이 아니다** | C | 진단 전용 |

## A. 회로를 정하는 것

### A-1. `normalize` — 다이오드-OR 하나로 되는가

| | |
|---|---|
| **소프트웨어** | `(env_c − δ) / (S − δ) > α_c` 에서 **S 를 무엇으로 만드나** |
| **하드웨어** | `xmax` = 정밀 max 회로 **추가 필요**. `xmix`/`xlse` = **다이오드 16개 + op-amp 1개**로 끝 |

`xmax`(하드 max)가 0.781 로 잘 나왔지만 **저항 divider 는 max 를 못 만든다.** 실제로
만들 수 있는 형태(`xmix`)로 바꾸니 −0.35pp 뿐이었고, 다시 다이오드의 지수 특성까지
넣은 `xlse`(soft max)는 **오히려 +6.7pp** 였다 (0.7778 → 0.8445).

> **회로를 더 정확히 흉내낼수록 좋아졌다.** 이건 우연이 아니라, soft max 가 조용한
> 프레임에서 분모를 16채널 평균 쪽으로 부드럽게 넘기기 때문이다.

### A-2. `lse_temp_frac` — 사실은 손잡이가 아니다

$$\text{frac} = \frac{n \cdot V_T}{\text{엔벨로프 스윙}} = \frac{1}{\text{음량}}$$

| | |
|---|---|
| **소프트웨어** | LSE 온도. 크면 부드러운 max, 작으면 하드 max |
| **하드웨어** | **요구 스윙 = 26 mV / frac.** 그게 프리앰프 이득을 정한다 |

분자는 물리가 26–39 mV 로 못 박는다. 우리가 고를 수 있는 건 **분모(프리앰프 이득)** 뿐이고
그것도 ×10 이 상한이다. 그래서 **frac 은 고르는 값이 아니라 결과값**이다.

학습이 요구하는 33 mV 를 만들려면 프리앰프는 **×1.4~4.2** — `×10`이 아니다.

> ⚠️ **0.78 은 철회됐다.** 이웃(1.2 / 2.0 = 둘 다 0.826)보다 1.8pp 튄 스파이크였고
> 시드 재현에서 무너졌다. 동료에게 넘길 것은 **평탄대 13–50 mV** 이지 한 점이 아니다.

### A-3. `xmax_floor_frac` → **δ** — 무음 하한선

| | |
|---|---|
| **소프트웨어** | 무음 squelch. δ=0 이면 순수 비율이라 무음에서 잡음÷잡음 |
| **하드웨어** | **δ = V_ref − 정지점.** 저항 2개. 자세히: `docs/diagrams/15_delta.svg`, `16_quiescent.svg` |

δ 는 **오차가 아니라 설계값**이다. α=0 이어도 임계가 정확히 δ 이므로,
**δ 만큼도 못 올라오는 채널은 절대 발화하지 못한다.**

#### δ 는 원래 **하드 max 의 문제를 막으려고** 생긴 것이다

무음 프레임(16채널 전부 가드 0.00100)에서 δ=0 이면:

| 정규화 | 무음에서 분모 S | 정규화값 | 결과 |
|---|---:|---:|---|
| **하드 max** (`xmax`/`xmix`) | 0.00100 (= 잡음) | **1.0000** | 잡음÷잡음 → **최대치로 발화** ❌ |
| **soft max** (`xlse`) | 1.61822 | **0.0006** | 사실상 0 → **알아서 꺼짐** ✅ |

LSE 는 **자기 바닥을 갖는다**: 모든 채널이 0 이어도 `S ≥ T·ln(16) = 1.617` 이다.
전형 음성 프레임 피크(0.72)보다 크므로, **무음에서 분모가 오히려 커져** 정규화값이
0 으로 떨어진다.

> **즉 `xlse` 에서는 δ 가 필요 없을 수 있다.** δ 는 `xmax`/`xmix` 시절의 유산이고,
> 우리가 확정한 회로에는 이미 자체 squelch 가 들어 있다. → §6e 가 `floor_frac=0` 을
> 후보에 포함해 확인한다.

#### 크기 — 만들려는 값보다 만드는 오차가 크다

| | mV | 전형 상승(31.9 mV) 대비 |
|---|---:|---:|
| δ | **0.108** | **0.34%** |
| 실제 comparator offset | ~1 | ~3% |

0.1 mV 를 저항 divider 로 맞추라는 건 불가능하다 — 저항 공차도 op-amp offset 도 그보다
크다. **그런데 맞출 필요가 없다**: δ≈0 이면 `(env−δ)/(S−δ) ≈ env/S` 라 floor 가 사실상
아무 일도 안 한다. → **`V_ref` 를 검출기 정지점(917.8 mV)에 둔다.**

#### 그리고 지금 값은 잘못된 것을 재고 있다

`sqrt(mel + 1e-6)` 의 `1e-6` 은 **수치 가드**다 — √ 는 0 에서 기울기가 무한대라
(`d/dx √x = 1/(2√x)`) 0 을 그대로 넣을 수 없다. 그래서 mel=0 인 프레임은
`√(1e-6) = 0.00100` 이 된다.

mel=0 인 프레임이 왜 생기나: GSC 클립은 1초가 "대충" 1초라 짧으면 **0 으로 패딩**한다.
0 의 STFT 는 0 이고 mel 도 0 이다. **그 프레임들이 전부 0.00100 한 점에 쌓인다** —
통계에서 말하는 **atom(질량점)** 이다.

무음이 **2.5%** 인데 `floor_frac` 이 **2.0%** quantile 을 요구하니, **quantile 이 atom
안**에 들어간다. 클립을 2048개로 늘린 것은 **분산**만 줄였고 **편향**은 그대로다 —
이제 가드 값으로 *안정적으로* 수렴한다. → **§6e** 가 후보를 좁힌다
(`xlse` 라면 **0** 이 유력하다).

### A-4. `comparators_per_channel` — 가장 싸게 산 정확도였다

| | |
|---|---|
| **소프트웨어** | 채널당 k 비트 thermometer code → 입력이 16×k 행 |
| **하드웨어** | 비교기 개수. **+17 µW/개** |

하드 max 에서 k=2 가 +2.5pp 였다. **그런데 soft max 가 k=1 로 이미 그보다 훨씬 많이
가져갔고**(0.8445 vs k=2 하드 max 0.8024), **둘이 겹치는지는 미측정**이다.
→ k=1 확정, k=2 는 `af_lse078_k2` 가 독립적 이득을 보이면 올린다.

### A-5. `spice_gain_restore` — soft max 에서 의미가 달라진다

| | |
|---|---|
| **소프트웨어** | 채널별 peak-norm 을 풀고 실제 이득(1.8 dB 편차)을 복원 |
| **하드웨어** | 채널 이득을 트리밍해야 하는가 |

껐던 근거는 *"채널별 threshold 가 흡수한다"* 였다. **하드 max 에서는 맞다** — α 가
채널별 상수라 채널별 스케일 오차를 흡수한다. **soft max 에서는 틀리다** — LSE 분모는
**16채널을 한 숫자로 섞으므로**, 1.23배 큰 채널 하나가 **모두의** 분모를 밀어올리고
채널별 상수로는 되돌릴 수 없다.

### A-6. `comparator_vos` — 보드를 만든 뒤로 미룬다

| | |
|---|---|
| **소프트웨어** | 임계에 더하는 오차 (normalized 단위) |
| **하드웨어** | 비교기 부품의 입력 오프셋 |

`train/config.py:116` 의 방침대로 **여기서 추측하면 baseline 에 임의값이 들어간다.**
회로가 확정되면 오프셋은 측정 가능한 고정값이 되고, 그때 진짜 숫자로 학습한다.
(`envelope_tau_ms` 를 baseline 에 안 넣는 이유와 같다.)

> 다만 기록 주의: EXPERIMENTS.md 의 *"비교기 오프셋은 병목이 아니다"* 는
> **normalized 0.002 = 0.064 mV 까지만** 본 결과다. 실제 ~1 mV 는 그 16배이므로,
> 그 문장은 **"측정한 범위 안에서"** 로 읽어야 한다.

## B. FPGA 를 정하는 것

### B-1. 창 위치 곡선 — 판정 규칙을 정한다

| | |
|---|---|
| **소프트웨어** | 단어가 창 안 어디 있어도 맞히나 |
| **하드웨어** | 슬라이딩 창이 성립하는가, 그리고 **후처리가 뭘 해야 하나** |

FPGA 는 always-on 이라 **누가 1초를 끊어주지 않는다.** 웨이크온이벤트는 죽었고
(상대 임계라 조용해도 프레임의 95.2% 가 발화), 100 ms 마다 판정하는 자유 구동
슬라이딩으로 간다. 그러면 한 단어가 **창 8개**에 걸린다.

측정: **낙폭 1.8pp** (`zero` 채움) → **위치는 사실상 공짜.**
→ 긴 캔버스 증강 불필요, **최대 확신도 선택 + 불응기**만 붙이면 된다.

> ⚠️ 같은 실험의 `white` 채움은 −15pp 였다. 그건 위치 얘기가 아니라
> **광대역 잡음이 상대 임계에 위협**이라는 뜻이다 — `room` 채움으로 실제 크기를 잰다.

### B-2. `envelope_win_ms` / `T` — 타이머와 레지스터 깊이

| | |
|---|---|
| **소프트웨어** | 프레임 격자, conv2 수용영역 |
| **하드웨어** | 10 ms 프레임 타이머, **16비트 × 100단 시프트 레지스터(1600 FF)** |

**T=128 을 바꾸지 말 것.** conv2(k=29, dilation 2) 유효 span 이 57 이고 conv1 stride 2 를
거치면 프레임이 절반이라, conv1 이후 ≥57 프레임이 필요하다. T=96/64 는 전부 붕괴한다.

### B-3. 모델 크기 — 접는 정도

10 Hz 실시간에 **0.6 MAC/cycle** 이면 되고 접은 설계가 KC705 의 **1.3%** 다.
**설계 압력은 용량이 아니라 검증 용이성**이다.

## C. 학습만의 것

### C-1. `aug_gain_db` — 하드웨어 흔적은 없지만 스펙을 바꾼다

| | |
|---|---|
| **소프트웨어** | 클립 게인을 흔들어 음량 강건성 |
| **하드웨어** | **직접적으로는 없다.** 다만 곡선이 평평해지면 **스윙 스펙이 헐렁해진다** |

`normalize=fixed` 에서는 −9pp 로 기각됐다 — 고정 임계 아래서 게인은 이미지를
**교란이 아니라 삭제**한다. **`xlse` 에서는 반대다**: 클립 게인을 바꾸는 것이
`lse_temp_frac` 을 바꾸는 것과 **수학적으로 같다.** 교란이 아니라 **우리가 강건해지고
싶은 바로 그 물리량**이다.

측정된 필요량: frac 스윕 **낙폭 27.4pp** (+12 dB 에서 −5.8pp, −12 dB 에서 −10.3pp).
→ `aug_gain_db [-12, +12]`. (§6c 가 계산한 ±1 dB 는 **너무 약하다** — 그 비교는
필요조건일 뿐이다.)

### C-2. `aug_time_shift_ms` — 종료됨

곡선 면적 **+0.33pp**, ±150 은 오히려 손해. 실패 이유가 중요하다: `_time_shift` 가
roll 이 아니라 **zero-pad** 라 단어가 **잘린다**. 잘림은 정보 소실이라 학습으로 복원
불가 — **고칠 수 없는 것을 측정하고 있었다.**

### C-3. `seed` — ⚠️ test 세트도 바꾼다

unknown 서브샘플과 합성 silence 가 둘 다 seed 로 뽑히므로 **테스트 클립의 약 20%**가
바뀐다. `af_lse078`(0.8445) 과 `af_lse078_s2`(0.8331) 은 **서로 다른 테스트 세트**에서
잰 값이다. "런간 변동 0.94pp" 에는 모델 변동과 **테스트 세트 변동**이 섞여 있다.

### C-4. `binarize` — 하드웨어 옵션이 아니다

AFE 에는 ADC 가 없다. 그게 AFE 의 존재 이유다. 이 스위치는 **"모델이 약한가"와
"1비트 입력이 손실인가"를 가르는 진단 전용**이다.

## D. 왜 이 구분이 중요한가 — 네 번 물렸다

| # | 무슨 일 | 교훈 |
|---|---|---|
| 1 | **`xmax` → `xmix`** | 시뮬에서 잘 나온 형태를 회로가 못 만든다. 형태 불일치를 **만들기 전에** 잡았다 |
| 2 | **δ** | 데이터 통계인 줄 알았는데 **회로 스펙**이었고, 게다가 zero padding 을 재고 있었다 |
| 3 | **`lse_temp_frac`** | 하이퍼파라미터처럼 보이지만 **1/음량**이다. 하나를 고르면 한 음량만 배운다 |
| 4 | **게인 증강** | `fixed` 에서 기각된 근거가 `xlse` 에는 **적용되지 않는다**. 정규화가 바뀌면 기각도 다시 봐야 한다 |

공통점: **소프트웨어에서 자유롭게 고를 수 있는 값처럼 보였는데, 물리가 이미 정해놓은
값이었다.** 새 손잡이를 만들 때마다 이 표의 어느 칸인지 먼저 정한다.

## E. 측정이냐 학습이냐 — 순서

**재학습이 필요 없는 것부터.** 그 결과가 어떤 100 에폭을 태울지 정한다.

| 셀 | 실험 | 재학습 | 시간 |
|---|---|---|---|
| §6a | 창 위치 곡선 | ❌ | 수 분 |
| §6c | 레벨 보정 | ❌ | 1~2분 |
| §6d | frac 스윕 | ❌ | 수 분 |
