# Global min-max 정규화 — 정확히 어떻게 하는가

AFE 파이프라인의 정규화 단계(`normalize: minmax`)를 코드 그대로 설명한다.
구현: [`../data/afe.py`](../data/afe.py) `AFEFrontend.envelopes()`.

## 한 줄 답

**오디오 파일(클립) 하나마다**, 그 클립의 **16채널 × 전체 시간 엔벨로프 이미지 전체**에서
**단 하나의 최소값(lo)과 하나의 최대값(hi)** 을 뽑아 `(x − lo)/(hi − lo)` 로 [0,1] 스케일한다.
채널별이 아니라 **16채널이 lo/hi를 공유**한다("global" = 채널 간 공유).

## 코드 (그대로)

```python
# env: [B, C, native_T]  = [배치, 16채널, ~100 시간창]
#   이 시점의 값 = 대역별 파워를 log(또는 √) 압축하고 10ms 창으로 max-pool 한
#   "대역 에너지 엔벨로프". (raw 오디오 진폭이 아님)
if self.cfg.normalize == "minmax":
    lo = env.amin(dim=(1, 2), keepdim=True)   # (채널, 시간) 축으로 min → 클립당 1개
    hi = env.amax(dim=(1, 2), keepdim=True)   # (채널, 시간) 축으로 max → 클립당 1개
    env = (env - lo) / (hi - lo + _EPS)        # [0,1]
```

- 텐서 `env`의 축: `dim0 = B`(배치=클립), `dim1 = C`(16채널), `dim2 = 시간창(~100)`.
- `amin/amax(dim=(1,2))` = **채널축과 시간축 둘 다** 뭉갬 → `dim0`(클립)만 남음.
  → **클립마다 lo/hi 하나씩**, 그 클립의 16×100 값 **전체**에서 계산.

## 파이프라인상 위치

```
파형 → STFT 파워 → 필터뱅크(16채널) → log/√ 압축 → (τ 평활) → 10ms max-pool
      → ★ global min-max 정규화 ★ → 채널별 학습 threshold → sign → 이진 {-1,+1}
```

즉 정규화되는 값은 **raw 소리 크기가 아니라** "필터+압축+창별 max"까지 거친 **대역 에너지
엔벨로프"** 다. (그래서 "소리 크기 최대/최소"라기보단 "대역 에너지 이미지의 최대/최소".)

## 구체 예 (3채널 × 4시간창 축소 예)

압축까지 끝난 엔벨로프가 이렇다고 하자:

| | t0 | t1 | t2 | t3 |
|---|---|---|---|---|
| ch0 | 0.20 | 0.80 | 0.30 | 0.10 |
| ch1 | 0.50 | 0.40 | **0.90** | 0.20 |
| ch2 | **0.00** | 0.10 | 0.15 | 0.05 |

- 이 클립의 **global 최대 = 0.90**(ch1,t2), **global 최소 = 0.00**(ch2,t0).
- 모든 값에 `(x − 0.00)/(0.90 − 0.00)` 적용:

| | t0 | t1 | t2 | t3 |
|---|---|---|---|---|
| ch0 | 0.22 | 0.89 | 0.33 | 0.11 |
| ch1 | 0.56 | 0.44 | **1.00** | 0.22 |
| ch2 | **0.00** | 0.11 | 0.17 | 0.06 |

→ 가장 센 점이 1.0, 가장 약한 점이 0.0. **조용한 ch2는 여전히 낮게, 센 ch1은 높게** 남는다
(= 채널 간 상대 크기 보존).

## 무엇이고 무엇이 아닌가

| 항목 | 이 방식? | 비고 |
|---|:--:|---|
| **클립(파일)별** | ✅ | 배치 dim0을 남김 → 발화 하나마다 lo/hi |
| **채널 공유(global)** | ✅ | 16채널이 lo/hi 하나를 공유(`dim=(1,2)`) |
| 채널별(per-channel) | ❌ | 그러면 채널 간 상대크기(스펙트럼 형상)가 지워짐 |
| 데이터셋 전체 기준 | ❌ | 전역 상수 아님. 매 클립 재계산 |
| raw 파형 진폭 기준 | ❌ | 필터+log/√+창별 max 뒤의 엔벨로프 기준 |

## 왜 이렇게 하나

1. **클립별 → 라우드니스 불변성.** 같은 단어를 크게/작게 녹음해도 [0,1]로 정규화돼 비슷해짐.
   (마이크 거리·게인 차이에 강건.)
2. **채널 공유(global) → 스펙트럼 형상 보존.** "지금 어느 대역이 센가"라는 채널 간 상대
   정보가 살아남고, 그걸 **채널별 학습 threshold**가 흡수해 분류에 쓴다. per-channel로 하면
   이 정보가 사라져 정확도가 떨어진다.

## 하드웨어 함의 (중요)

**클립별·채널공유 min-max는 본질적으로 AGC(자동이득조절)** 다 — 매 발화의 동적범위를
훑어 [0,1]로 맞추니까. 그런데 **실제 AFE의 고정 R7/R8 비교기 임계엔 이런 AGC가 없다.**
따라서 이 정규화는 **소프트웨어 이상화**이며, 하드웨어로 가려면 (a) 앞단에 공유 AGC 블록을
두거나 (b) `normalize="none"`(절대 임계)로 재학습해야 한다. 이 때문에 소프트웨어 정확도가
실물보다 낙관적일 수 있다(HF 소신호가 오프셋에 묻히는 문제를 sim이 가림 —
[`phase_b_summary.md`](phase_b_summary.md) 및 비교기 마진 논의 참조).

## 관련 설정 (`configs/base.yaml`)

- `afe.normalize: minmax` — 위 방식. `none`으로 끄면 정규화 없이 절대값 사용(하드웨어 충실,
  단 라우드니스 불변성 상실). 코드상 `minmax`/`none`만 지원.
