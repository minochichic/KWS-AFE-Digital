# 문제 2 — 하드웨어 인지 학습(HAT) + 아키텍처 대안

## 2.1 가장 급한 것: 오프셋 인지 학습 (증거 확보됨)

우리 모델은 **이상 비교기**(`sign(env−thr)`, 오프셋 0)로 학습됐다. 실제 비교기 오프셋을
주입해 평가하니:

| vos (정규화 임계 std) | 대응 | test acc |
|---:|---|---:|
| 0.000 | 이상 | **0.8016** |
| 0.020 | | 0.6184 |
| **0.035** | **프리앰프 有** | **0.4695** |
| 0.100 | **프리앰프 無** | 0.2177 |

**결론**: 하드웨어 비이상을 학습에 넣지 않으면 실물에서 무너진다. 프리앰프로 오프셋을
1/3로 줄여도 0.47 — **아날로그 개선만으론 불충분**하고 **학습이 흡수해야 한다**.

### HAT에 넣어야 할 비이상 목록

| 비이상 | 모델링 방법 | 상태 |
|---|---|---|
| 비교기 오프셋 Vos | 임계에 가우시안 주입 (`comparator_vos`) | ✅ 구현됨 |
| 검출기 데드존 | `relu(amp − dz)` | ✅ 구현됨(단 학습 데드존은 정확도 하락) |
| **소자 공차** (E12/E24, f_c/Q/gain 편차) | 필터뱅크 행렬 perturbation 증강 | ❌ 미구현 |
| **정적 vs 랜덤 오프셋** | per-device 고정 draw + 트림 잔차 | ❌ 미구현 (문제 1 방안 B) |
| 온도 드리프트 | 느린 임계 이동 | ❌ 미구현 |

### 즉시 할 실험 (코드 변경 불필요)

```python
# ① 프리앰프 수준에서 오프셋-인지 학습
cfg = load_config('configs/base.yaml', {
    'tag':'sc_v2_spice_sqrt_vos035',
    'afe.filterbank_source':'spice', 'afe.compression':'sqrt',
    'afe.comparator_vos':0.035})
# ② 프리앰프 없음 수준: 'afe.comparator_vos':0.10
```
**기대**: 학습이 오프셋을 흡수해 0.47 → 회복. ①이 ②보다 잘 회복하면 **프리앰프의 정확도
가치가 숫자로 확정**된다. (이게 문제 1과 2를 잇는 다리.)

## 2.2 아키텍처 대안 — 냉정한 평가

### Hello Edge (Arm) 실측 (12-class GSC, **MFCC 입력**, 8-bit)

| 모델 | S: acc/mem/ops | M | L |
|---|---|---|---|
| LSTM | 92.9% / 79.5 KB / 3.9 M | 93.9% / 198.6 KB / 19.2 M | 94.8% / 498.8 KB / 48.4 M |
| GRU | 93.5% / 78.8 KB / 3.8 M | 94.2% / 200.0 KB / 19.2 M | 94.7% / 499.7 KB / 48.4 M |
| CRNN | 94.0% / 79.7 KB / 3.0 M | 94.4% / 199.8 KB / 7.6 M | 95.0% / 499.5 KB / 19.3 M |
| **DS-CNN** | **94.4% / 38.6 KB / 5.4 M** | 94.9% / 189.2 KB / 19.8 M | **95.4%** / 497.6 KB / 56.9 M |

### ⚠️ 직접 비교 금지 — 입력이 다르다

이 94–95%는 **full-precision MFCC 입력**이다. 우리는 **16채널 1비트** 입력이다.
정보량이 근본적으로 다르다. 실제로:

- Cerutti(같은 이진 AFE): 8ch **76.3%**, 64ch **86.0%** — 이진 입력의 천장이 훨씬 낮다.
- 우리: 이상 mel 16ch 0.85 / 실제 SPICE 16ch 0.80.
- **conv2 dense(파라미터 3.4×)로도 spice 정확도가 안 올랐다** → **병목은 모델이 아니라 입력**.

**따라서 아키텍처를 바꿔서 95%에 가는 길은 없다.** 갭은 입력(채널 수·이진화)에 있다.
아키텍처 교체의 진짜 가치는 **정확도가 아니라 하드웨어 효율**이다.

### 각 대안의 우리 타깃 적합성

| 후보 | 정확도 기대 | FPGA/이진 적합성 | 판정 |
|---|---|---|---|
| **MatchboxNet (현재)** | 기준 | 1D TCS depthwise-separable + residual, 전부 전방향 | 유지 |
| **DS-CNN** | ≈ 동급 (둘 다 depthwise-separable) | 유사, 2D conv | 마진 이득 작음 |
| **GRU / LSTM** | 파라미터 효율 좋음 | ❌ **순차 의존**으로 시간축 펼침 불가, sigmoid/tanh는 이진화 난망, 이진 RNN 학습 불안정 | 비권장 |
| **CRNN** | ops 효율 우수(7.6 M@M) | ❌ RNN 부분 동일 문제 | 비권장 |

> **핵심**: MatchboxNet은 이미 DS-CNN과 같은 depthwise-separable 계열이다. 구조 교체보다
> **입력 정보량(채널 수)** 과 **학습 기법**이 레버다.

## 2.3 이진 학습에 특화된 기법 (진짜 기회)

새 아키텍처보다 **이진 + 하드웨어 비이상**에 맞춘 학습법을 만드는 쪽이 유망하다.

| 기법 | 내용 | 우리 근거 |
|---|---|---|
| **오프셋/노이즈 인지 학습** | 학습 중 Vos·드리프트 주입 | ✅ 필요성 증명됨(0.80→0.47) |
| **편차 강건 학습** | f_c/Q/gain perturbation + E12/E24 스냅 증강 | 제작 공차 대비 |
| **지식 증류(KD)** | mel+√ 0.85 교사 → spice 이진 학생 | 이진 학생의 약한 gradient 보완 |
| **점진적 이진화** | full→2bit→1bit 스케줄, latent 유지 | BNN 표준 기법 |
| **학습형 STE clip / PACT** | `ste_clip`을 학습 파라미터로 | 현재 고정 1.0 |
| **이벤트율 정규화** | threshold에 발화율 페널티 → 인터럽트=전력 | CLAUDE.md 3.5 메모 |
| **다중비트 잔차 이진화** | 정확도 부족 시 2비트 폴백 | 하드웨어 비용↑ 트레이드오프 |

**증강은 국면 의존**: 과소적합 국면에서 파형 증강은 역효과였다(#8, −1pp). 그러나
**하드웨어 비이상 증강은 성격이 다르다** — 테스트 분포(실물)에 맞추는 것이므로 유효할 것.

## 2.4 실행 순서 (권장)

1. **오프셋-인지 학습 2건** (vos=0.035 / 0.10) → 회복량 및 프리앰프 가치 확정. *(코드 변경 없음)*
2. **정적 오프셋 + 트림 잔차** 모델링 → 교정이 얼마나 되돌리는지 (문제 1 방안 B와 연동).
3. **편차 강건 학습**(필터 perturbation 증강) 추가.
4. (선택) **KD**로 이진 학생 끌어올리기.
5. 아키텍처 교체는 **정확도 목적이면 비권장**; FPGA 자원이 문제일 때만 DS-CNN류 검토.
6. **채널 수 16→24/32**가 정확도 천장의 유일한 물리 레버 — CLAUDE.md 고정이므로 **상의 필요**.
