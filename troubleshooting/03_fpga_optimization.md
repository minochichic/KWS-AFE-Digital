# 문제 3 — FPGA 하드웨어 최적화 (folding 등)

## 3.1 출발점: 현재 모델의 실제 비용

`BinaryMatchboxNet.describe()` 출력 기준 (C=64, T=128, separable):

| 스테이지 | 파라미터 | 정밀도 | 가중치 메모리 |
|---|---:|---|---:|
| conv1 | 22,784 | int8 | 22.3 KB |
| b1 | 23,616 | binary | 2.9 KB |
| b2 | 10,624 | binary | 1.3 KB |
| b3 | 10,880 | binary | 1.3 KB |
| conv2 | 10,432 | binary | 1.3 KB |
| conv3 | 16,640 | int8 | 16.3 KB |
| conv4 | 1,548 | fixed(16b 가정) | 3.0 KB |
| **합계** | **96,524** | (이진 57.6%) | **≈ 48.3 KB** |

> **첫 번째 발견**: **이진 스테이지는 파라미터의 58%지만 메모리는 겨우 ~14%**(6.8 KB).
> **int8 prologue/epilogue(conv1+conv3)가 메모리의 80%**(38.6 KB)를 먹는다.
> → 메모리 최적화 타깃은 이진 블록이 아니라 **conv1/conv3**이다.
> (참고: Hello Edge DS-CNN-S는 전체 38.6 KB로 94.4% — 우리 int8 두 층만 한 크기.)

## 3.2 두 번째 발견: 완전펼침은 이 문제에 과대 설계

- KWS 분류율: **2–10 Hz** (Cerutti는 2 Hz).
- FPGA @100 MHz → 초당 1e8 사이클 → **분류 1회당 ~1e7 사이클** 여유.
- 필요 연산: ~수 MOp 규모(⚠️ 정밀 카운트 미실시).
- → **1 op/cycle짜리 작은 엔진으로도 시간이 남는다.**

즉 완전펼침(fully-unrolled)은 시간축으로 **~1e6–1e7배 과대**하다. CLAUDE.md 5의
"완전 펼침 가정"은 재검토 대상이다.

| 방식 | 장점 | 단점 | 이 프로젝트 적합성 |
|---|---|---|---|
| **완전펼침** | 가중치를 LUT에 하드코딩(메모리 0), 최고 처리량 | 면적 폭발, 99.99% 유휴 | ❌ 과대 |
| **folding(재사용)** | 면적 최소, 자원↔지연 조절 | 가중치 메모리(BRAM) 필요, 제어 복잡 | ✅ **권장** |

**folding 설계 축** (FINN 스타일): PE(출력 병렬) × SIMD(입력 병렬)를 낮게 잡아 면적을 줄이고
남는 시간을 쓴다. 시간 여유가 압도적이므로 **가장 작은 엔진 + 최대 folding**이 출발점.

## 3.3 이진 연산 최적화 (CLAUDE.md 3.4와 일치)

- **BN → 정수 임계 융합**: 학습 후 `floor(β'/γ')` 하나로 접어 비교 1회. 곱셈기 제거. **필수**.
- **비트 팩킹 + XNOR/popcount**: `2·popcount(XNOR) − N`. popcount는 LUT6 압축기 트리.
- **depthwise ≠ pointwise**: 팩킹 이득은 **pointwise(1×1)** 에서 극대. depthwise는 채널을
  안 섞어 이득이 작다 → **두 PE를 통합하지 말 것**.
- **conv1은 곱셈기 불필요**: 입력이 ±1이라 int8 가중치의 **부호 있는 누산**으로 구현.
  (conv3만 진짜 int8×int8 → DSP 필요.)
- **residual 정수 누산**: 마지막 pointwise·skip은 α 미적용 정수 유지, 임계 1회.

## 3.4 세 번째 발견: µW 목표에서 진짜 적은 **정적 전력**

듀티비가 극단적이다 — 분류 1회에 1e7 사이클 중 실제 계산은 극히 일부, 나머지는 유휴.

- **동적 전력은 작고, 누설/정적 전력이 지배**한다.
- 일반 SRAM FPGA의 정적 전력은 **수 mW~수십 mW** 급 → **µW 예산과 3–4 자릿수 충돌**.
- 대책:
  1. **울트라 저전력 FPGA 계열** (예: Lattice iCE40 UltraPlus, Microchip PolarFire 계열
     — ⚠️ 실제 정적전력 **데이터시트 확인 필요**).
  2. **클록 게이팅 / 전력 게이팅** — 이벤트 없을 때 완전 정지 (AFE가 이벤트 기반이라 궁합 좋음).
  3. **FPGA는 프로토타입, 전력 수치는 ASIC 기준**으로 리포트 (Cerutti도 CUTIE ASIC 가정으로
     15.7 nJ/분류를 계산).

> **정직한 정리**: FPGA에서 "분류당 ≤15 mJ"는 쉽지만, Cerutti급 **µW 상시대기**는 FPGA
> 정적전력 때문에 어렵다. 목표를 (a) FPGA=기능 검증, (b) 전력=ASIC 추정으로 분리해야 한다.

## 3.5 추가 최적화 아이디어

| 아이디어 | 내용 | 기대 |
|---|---|---|
| **스트리밍/이벤트 구동** | 128프레임 버퍼링 대신 프레임 도착마다 처리 | 지연·버퍼↓, AFE 이벤트 특성과 정합 |
| **conv1/conv3 경량화** | 메모리 80%를 차지 → 채널수·커널 축소 또는 4-bit 양자화 | 메모리 최대 절반↓ |
| **가중치 압축** | 이진 가중치 희소성/반복성 활용 | BRAM↓ |
| **T 축소** | 현재 T=128 고정(conv2 span 57 제약) | conv2 커널 줄이면 T↓ 가능 → 연산·버퍼↓ |
| **레이어 융합** | BN+sign+pack을 한 파이프 단으로 | 레지스터↓ |

## 3.6 실행 순서

1. **연산량(MOp) 정밀 카운트** — 레이어별 MAC/XNOR-popcount를 실제로 세어 표로.
   (지금까지 "~5 MOp"는 **추정**이며 근거 없음.)
2. **folding 설계점 탐색** — 목표 분류율(2/10 Hz)에서 PE·SIMD를 낮춰 필요한 최소 자원 산출.
3. **자원 추정** — LUT/FF/BRAM/DSP를 folding 계수별로 (합성 전 해석적 추정 → 이후 합성 검증).
4. **정적 전력 조사** — 후보 FPGA 계열의 정적전력 확인, µW 목표와의 격차 명시.
5. **export 경로 확정** — BN-임계 융합 + 비트팩킹 내보내기(`export/`)를 folding 구조에 맞춰 설계.
