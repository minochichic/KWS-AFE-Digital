전체 시계열 기록은 [`docs/experiments_log.md`](../docs/experiments_log.md)에 있다.
여기는 **결론과 그 근거**만 남긴다.

## 1. 정확도 사다리 — 손실의 완전 분해

세 실험 모두 **네트워크 내부(B1~B3, conv2)는 이진 그대로**이고 입력 경로만 다르다.
`binarize=False`는 비교기만 제거하는 진단 스위치다.

| 런 | 입력 | test |
|---|---|---:|
| `nn_cont_mel64` | 64채널 **연속** log-mel + minmax | **0.9198** |
| | ↓ **−5.8pp** — 프론트엔드 (64→16ch, mel→spice, log→√, minmax→xmax) | |
| `nn_cont_afe16` | 16채널 **연속** spice+√+xmax | **0.8617** |
| | ↓ **−8.0pp** — **비교기 (1비트화)** | |
| `af_k2` | 16채널 **2비트** (비교기 2개) = **현재 모델** | **0.8024** |
| `af_k1_ref` | 16채널 **1비트** | **0.7778** |

**두 가지가 확정된다:**

1. **모델은 병목이 아니다.** 가중치·활성이 전부 이진인 상태로 좋은 입력에서 0.920이 나온다.
2. **연속값 16채널 천장이 0.8617**이다. 정규화를 완벽하게 만들어도(실현 불가능한 minmax
   0.802) 85%에 못 미치므로, **남은 격차를 정규화에서 짜낼 수 없다.**

## 2. 정규화 — 최종 확정

전부 spice + √ + 16채널, 동일 모델·학습 설정. `comparator_vos = 0` 기준.

| 정규화 | test | 하드웨어 | 피드백 루프 |
|---|---:|---|---|
| `minmax` | 0.802 | ❌ 구현 불가 (클립 전체 max = 미래 참조) | — |
| `agc` + 캘리브레이션 | 0.789 | VGA | ⚠️ 있음 |
| **`xmax` floor=0.05** | **0.781** | 정밀 max (뱅크 공유 1~2개) | ✅ **없음** |
| `xmax` floor=0.02 | 0.776 | ″ | ⚠️ §4 퇴화 |
| `xmax` floor=0.10 | 0.756 | ″ | ✅ |
| `fixed` q=0.75 | 0.726 | 없음 | — |
| **`xmix` floor=0.02** | **0.778** | ← **최종 형태** (회로가 실제로 만드는 것) | ✅ |
| `xmix` floor=0.05 | 0.732 | ″ | ⚠️ 채널 4개 사망 |

### `xmix` — 하드웨어 형태의 대가는 −0.35pp

저항 분압은 max를 못 만들고 선형 혼합만 할 수 있다. 그 형태로 바꾼 결과:

| | test | 차이 |
|---|---:|---|
| `xmax` floor=0.05 | 0.7813 | 기준 |
| **`xmix` floor=0.02** | **0.7778** | **−0.35pp** |

**저항 분압으로 구현해도 정확도가 거의 그대로다.** §5-3의 형태 불일치는 이것으로 해소됐다.

> ⚠️ **xmix의 권장 floor는 0.02로, xmax의 0.05와 다르다.** floor=0.05로 학습하면
> ch3/4/5/15의 α가 1.0에 붙어 **4채널이 사실상 죽고** 0.732로 떨어진다. α=1은
> "그 순간 최대일 때만 발화"라 정보를 거의 싣지 못한다.

**AGC와 0.8pp 차이**다. 피드백 루프(발진·어택/릴리즈·첫 단어 문제)를 감수할 이유가
사라졌으므로 **AGC는 폐기**한다.

**오프셋 강건성** (floor=0.05): vos 0 / 0.001 / 0.002 → 0.7813 / 0.7835 / 0.7801.
평평하다 → **비교기 오프셋은 병목이 아니다.**

## 4. 함정 — 우리를 물었던 것들

기록해두는 이유: **전부 "시뮬은 되는데 하드웨어는 못 하는" 종류**였고, 같은 실수를
반복하지 않기 위해서다.

### 4-1. R7/R8 매핑 — 13/16 채널이 항상 ON

초기 매핑이 v_env 최소값을 `from=8ms`에서 쟀는데 τ=4.7 ms이므로 **1.7τ밖에 안 지난
기동 과도**를 바닥으로 착각했다. 실제 모델로 재측정하니 정지점 918.38 mV가 나왔고
동료 값(917.83)과 0.55 mV 이내로 일치 → **측정창 오류**였지 모델 오류가 아니었다.

### 4-2. "스윙" — 리플과 상승을 혼동

채널별 스윙을 **정상상태 리플**로 쟀더니 86 → 1.2 mV로 나와 ch14/15가 사용 불가라는
결론이 나왔다. 비교기가 검출하는 것은 **정지점 위로의 상승**이고, 그건 28–65 mV로
거의 균일하다. `analog/AFE_tuning/artifacts/v15_circuit_review.md` §3-3에 오류 표시.

### 4-3. floor를 데이터셋 최댓값 기준으로

`xmax` 첫 구현에서 floor를 데이터셋 피크의 비율로 잡았더니, 피크가 중앙값 프레임의
**약 200배**라 floor가 **87%의 프레임을 지배**해 `xmax`가 사실상 `fixed`로 퇴화했다.
→ **프레임 분위수** 기준으로 변경.

### 4-4. floor가 sqrt 수치 가드 위에 착지

엔벨로프는 `sqrt(mel + 1e-6)`이라 바닥이 정확히 **1e-3**이다(0 나누기 가드). 무음·
제로패딩 프레임에서는 16채널이 전부 이 값이 되고, `xmax`가 이를 자기 자신으로 나눠
**1.0 → 전 채널 발화**. **무신호가 "가장 활발한 이미지"** 가 된다.

`floor_frac = 0.02`의 floor가 정확히 그 가드 값이라 보호가 전혀 없었다:

| floor_frac | floor | 가드 대비 | 제로 클립 발화 | ×0.01 조용한 클립 | 정상 음성 |
|---|---|---|---|---|---|
| **0.02** | 0.00100 | **1.0×** | **1.000** ⚠️ | **0.538** ⚠️ | 0.386 |
| 0.05 | 0.00634 | 6.3× | 0.000 ✅ | 0.155 | 0.366 |

`f=0.02`에서는 **조용한 클립이 정상 음성보다 더 발화**한다. 영향 프레임 3.3%.
→ `init_fixed_scale()`에 경고 추가(clamp가 아니라 warn — 기존 런 숫자를 조용히 바꾸지
않기 위해). 그리고 **f=0.05(0.781)가 f=0.02(0.776)보다 높다** — 그 2pp는 실익이 아니었다.

### 4-5. xmix 구현 중 잡은 3개

| 증상 | 원인 | 조치 |
|---|---|---|
| 무음에서 부등호 뒤집힘 | `S ≤ d`면 분모가 음수 | 볼록결합이라 발화 불가 → 상수 "off" |
| **init α = −15** | `S`가 `d`보다 조금만 커도 몫이 −59, 값의 89%가 음수 | 값을 [−1,1]로 클램프 (비교기는 "얼마나 아래"를 출력 못 함) |
| 한 채널이 **전 프레임 발화** (전체 비트 4.9%) | 죽은 채널의 α가 정확히 −1 = 무음 센티넬, `sign(0)=+1` | α를 [0,1]로 클램프 (저항비의 물리적 범위) |

## 5. Cerutti 대조 — 우리는 곡선 위에 있다

| 채널 수 | 정확도 | 출처 |
|---|---:|---|
| 8 | 76.3% | Cerutti Fig.6 |
| **16** | **78.1%** | **우리 (xmax floor=0.05)** |
| 64 | 86.0% | Cerutti 결론 |

두 점을 **채널 수 2배당 +3.2pp**로 로그선형 보간하면 16채널 예측치 **79.5%**.
측정 78.1%은 **1.4pp** 안쪽이다.

> **우리가 뭘 잘못한 게 아니라, 16채널이 부족한 것이다.**

같은 곡선 외삽: 32ch ≈ 82.8%, 48~64ch ≈ 85~86%.

## 6. 부수 발견 — "silence" 클래스가 음성보다 3배 시끄럽다

| | RMS |
|---|---|
| 음성 (키워드 10종) | 0.0659 |
| **silence (배경잡음 크롭)** | **0.1925** |

`_background_noise_`가 풀스케일 녹음(설거지·수돗물·운동자전거)이기 때문이다. 그 결과:

| 정규화 | 무음 발화율 / 음성 발화율 |
|---|---|
| `fixed` | **5.19×** |
| `xmax` floor=0.05 | 1.93× |

`fixed`에서는 네트워크가 **"얼마나 많이 켜졌나"라는 음량 단서만으로** silence를 골라낼
수 있었다. `xmax`는 그 단서를 걷어내고 패턴을 쓰게 만든다 — **그러고도 정확도가
올랐다**는 것이 이 방향이 옳다는 근거다.

## 8. 비교기 비트 수 — 가장 싸게 산 정확도

| 설정 | test | 비교기 전력 | 파라미터 |
|---|---:|---|---|
| k=1 (1비트) | 0.7778 | 16.7 µW | 96,524 |
| **k=2 (2비트)** | **0.8024** | **33.4 µW** | 119,052 |

**+2.5pp를 +17 µW에.** 양자화 손실 8.4pp(0.862 → 0.778)의 **31%를 회수**했고,
0.8024는 **실현 불가능했던 minmax 상한(0.802)과 같은 값**이다.

두 번째 비교기가 실제로 일한다는 증거:

* 학습된 임계 간격이 **0.0513 ~ 0.5346** — 0으로 붙은 쌍이 없다 (붙으면 같은 비트를
  두 번 인코딩하는 낭비다)
* 죽은 비교기 2/32 = k=1의 1/16과 **같은 비율** — 채널을 죽이지 않았다
* k=1을 같은 코드 경로로 재실행해 **0.7778을 정확히 재현** → `repeat_interleave`가
  k=1에서 무해함이 확인됐다

> ⚠️ 입력이 16→32행이 되며 conv1이 커져 파라미터가 23K 늘었다. 이득이 정보(2비트)
> 때문인지 용량 때문인지 완전히 가르려면 k=1에 C를 키운 대조군이 필요하다.
