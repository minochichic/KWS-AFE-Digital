## 우리가 가정하던 것과 무엇이 다른가

**밴드는 125–5000 Hz.** 우리가 −0.3pp(잡음)로 재놨던 그 밴드다. 여기까지는 일치.

그런데 **필터뱅크 자체는 우리 `_125_5000` 뱅크가 아니다.** 두 가지가 구조적으로 다르다:

| | 우리 설계 | **동료 보드** |
|---|---|---|
| 채널 배치 | **mel 등간격** | **로그 등간격** (비율 1.27880 = 40^(1/15), 편차 0.0000%) |
| Q | 2.13 → 7.65 (상승) | **4.5 고정** (정 Q 필터뱅크) |
| 검출기 이득 R5/R4 | 4.7 | **10.0** |
| 프리앰프 | 없음 | **×10** (1 + Rpre2/Rpre3 = 1 + 90/10) |
| 검출기 op-amp | 상위 6채널 TLV9041D | **전 채널 OPA379** ✅ |

→ **`fx_band125` = 0.814 는 이 보드의 숫자가 아니다.** 밴드만 같고 필터 모양이 다르다.

## ⚠️ 한계 — 하위 채널은 우리 STFT 로 분해가 안 된다

Q=4.5 고정이라 대역폭이 `f_c/4.5` 로 f_c 에 비례한다. 하위 채널이 아주 좁아진다:

| ch | f_c | BW | STFT 빈(31.25 Hz) 대비 |
|---:|---:|---:|---:|
| **0** | 124.5 | **27.5 Hz** | **0.88 빈** |
| **1** | 158.5 | 35.8 Hz | 1.15 빈 |
| 2 | 201.8 | 45.5 Hz | 1.46 빈 |
| 15 | 5011.9 | 1080 Hz | 34.6 빈 |

**ch0 의 통과대역(27.5 Hz)이 STFT 빈 하나(31.25 Hz)보다 좁다.** 게다가 STFT 창이 25 ms 라
그 자체 분해능이 ~40 Hz 로 ch0 의 27.5 Hz 보다 **넓다**. 즉 우리 시뮬은 원리적으로
ch0 를 실제보다 **뭉툭하게** 본다.

**실물 필터가 시뮬보다 날카롭다**는 뜻이므로, 이 방향의 오차는 정확도를
**과소평가**하는 쪽이다. ch2 가 Q 3.14 / 이득 24.28 dB 로 보였던 것이 바로 이
현상이고, 미세 스윕으로 재니 4.44 / 25.9 dB 였다 — 회로는 멀쩡하다.

해소하려면 `n_fft` 를 키워야 하는데(512 → 1024 면 빈 15.6 Hz), 그건 STFT 프론트엔드
변경이라 별건이다. 지금은 **한계를 알고 진행**한다.

## C3 가 처음으로 실제 τ 를 준다

CLAUDE.md §2.5 는 "논문에 τ 수치가 없다, 추정일 뿐"이라고 적어놨다. 이제 값이 있다.
방전 경로는 R5+R4 = 550 kΩ (D2 가 꺼지면 v_env 가 R5→R4→v_filt 로 빠진다):

| ch | C3 | τ = (R4+R5)·C3 |
|---|---:|---:|
| 0–3 | 39 nF | **21.45 ms** |
| 4–7 | 15 nF | 8.25 ms |
| 8–11 | 5.6 nF | 3.08 ms |
| 12–15 | 2.2 nF | 1.21 ms |

(토폴로지에서 계산한 **추정**이다. 확정하려면 transient 로 재야 한다.)

**CLAUDE.md §3.2 가 τ 를 baseline 에서 뺀 근거 두 개 중 하나가 무너졌다:**
"논문에 수치가 없어 임의값이 된다" — 이제 임의값이 아니다. 그리고
"τ < window 면 효과가 거의 없다" — 하위 8채널의 τ(21.45 / 8.25 ms)는
`envelope_win_ms = 10 ms` **보다 길거나 비슷하다.** 즉 하위 채널에서는 평활이
프레임을 넘어 번진다.

→ **τ ablation 이 이제 제대로 된 질문이 됐다.** 다만 CLAUDE.md §3.2/§5 가
"baseline 에 켜지 말 것"이라고 못박고 있으므로, 켜는 것은 별도 결정 사항이다.

## 임계값: 동료가 이미 정해놨다

R7/R8 로 **Vthr 0.950~0.990 V** (검출기 정지점 0.9 V 위 50~90 mV). 채널별로 다르다.

우리 학습은 임계값을 **스스로 찾는다.** 학습이 끝나면 두 벌의 숫자가 생기고,
다르면 동료에게 알려야 한다. 그 대조는 `experiments/threshold_volts.py` 가 한다.

**단, PCB 로 얼리기 전에 남은 문제:** 채널별 임계값은 런마다 불안정하다
(정확도가 거의 같은 두 런 사이 순위상관 +0.53). 총합은 안정적이다.
한 런의 16개 숫자를 그대로 저항으로 새기면 재현되지 않는 값을 새기는 것이다.
시드 반복으로 평균·분산을 먼저 재야 한다. `../../docs/ABLATIONS.md` 참조.

## STFT 창과 필터의 시간 척도 (2026-08-30)

이 보드는 **정 Q 필터뱅크**(Q=4.5 고정)다. 그래서 채널마다 대역폭도 시간 척도도
다르다 — 대역폭 `f_c/Q`, 링잉 `Q/(π·f_c)`:

| ch | f_c | 대역폭 | 링잉 | 프레임(10 ms) 대비 |
|---:|---:|---:|---:|---:|
| **0** | 125 | **27.8 Hz** | **11.46 ms** | **1.15×** |
| 1 | 160 | 35.5 Hz | 8.96 ms | 0.90× |
| 2 | 204 | 45.4 Hz | 7.01 ms | 0.70× |
| 8 | 894 | 198.7 Hz | 1.60 ms | 0.16× |
| **15** | 5000 | **1111 Hz** | **0.29 ms** | 0.03× |

**시간 척도가 채널 간 40 배 다르다.** 우리 시뮬은 **STFT 창 하나(25 ms)** 를 16채널에
똑같이 씌우므로, 그 하나가 모든 채널에 맞을 수가 없다.

### 어긋나는 방향이 채널에 따라 반대다

| | 실물 | 시뮬 (창 25 ms) | 결과 |
|---|---|---|---|
| **하위** (ch0–1) | 대역폭 27.8–35.5 Hz | 분해능 **40 Hz** | 창이 더 넓다 → **실제보다 뭉툭하게 본다** |
| **상위** (ch12–15) | 링잉 0.3–0.6 ms | 창 **25 ms** | 창이 훨씬 느리다 → **날카로운 이벤트가 2~3 프레임에 번진다** |

중간 채널(ch2–11)만 대략 맞는다.

**근본 원인**: 실물은 정 Q(채널마다 다른 시간 척도), STFT 는 정 대역폭(전 채널 동일).
제대로 맞추려면 constant-Q 변환이나 웨이블릿이어야 한다. `n_fft` 를 키우는 것으로는
안 된다 — 제로패딩은 빈만 촘촘하게 하고 분해능(= 1/창길이)은 그대로다.

### ⚠️ ch0 는 실물에서도 프레임을 넘어 울린다

링잉 **11.46 ms > 프레임 10 ms**. 즉 ch0 의 응답은 하드웨어에서도 한 프레임 안에
안 끝난다. CLAUDE.md §2.6 의 시간 척도 계층("τ < window 라 window 안에 펄스가 여러
개")이 **이 채널에서는 성립하지 않는다** — 필터 자체가 프레임보다 느리다.

C3 의 τ(ch0–3 에서 21.45 ms)와 합치면 하위 채널은 **필터도 검출기도 프레임보다
느리다.** 그 채널들의 "10 ms 프레임"은 독립적인 관측이 아니라 서로 겹친 값이다.

이건 시뮬의 결함이라기보다 **하위 채널의 시간 해상도가 원래 그만큼 없다**는 사실이고,
`firing_stability` 에서 ch0 가 클립의 49.7% 에서 아예 안 켜지는 것과도 이어진다.

# 디지털 인터페이스 — 거버에서 읽은 확정 사실 (2026-09-09)

여기까지가 아날로그 사슬이었다면, 이 절은 **비교기 오른쪽**이다. 근거는 추측이나
전언이 아니라 **동료가 보낸 거버 파일 자체**다.

KiCad 는 X2 확장으로 구리층에 네트/패드 속성을 박아넣는다. 그래서 넷리스트가 없어도
배선을 읽을 수 있다 — 이 절의 모든 표가 거기서 나왔다:

```bash
grep -h -o 'TO\.N,[^*]*' *_Cu.gbr | sort -u                 # 네트 목록
grep -A 3 'TO\.P,<refdes>,' KWS_Layout-F_Cu.gbr             # 그 부품 패드의 네트
```

**회로도 그림을 눈으로 읽는 것보다 이쪽이 확실하다.** 핀 번호를 잘못 읽을 여지가
없고, 도면에 안 나온 시트 사이 연결까지 잡힌다.

## 1. 전원 — 3.3 V 하나로 보드 전체가 돈다

```
TO.P,J101,1 -> /3V3_IN        TO.P,U102,1 IN -> /3V3_IN,  5 OUT -> 1.8V
TO.P,J101,2 -> GND            TO.P,U103,1 IN -> /3V3_IN,  5 OUT -> MIC_0V9
```

```
J101 핀1 (3.3 V) --+-> VCCB   (레벨 시프터 U104, U105)
                   +-> U102 TPS7A2018 -> 1.8 V     (아날로그 + 시프터 VCCA)
                   +-> U103 TPS7A2009 -> MIC_0V9   (마이크 바이어스)
J101 핀2 --------- GND
```

두 LDO 다 `EN` 이 `IN` 에 묶여 있어 3.3 V 가 들어오면 무조건 켜진다.

### ⚠️ 이것이 `docs/ICD.md` 7.1 의 전원 결정을 대체한다

2026-09-01 에 *"전원은 U103 의 3.3 V -> 기판 LDO -> 1.8 V"*, 즉 **FPGA 보드에서
뽑는다** 고 결정했었다. `docs/hanback_kit.md` 4.5 는 그걸 킷이 바뀐 뒤에도 유지해
*"J6 핀 1·2 의 VCC5V 에서 뽑는다"* 로 옮겨 적었다.

**실제 기판은 그렇게 만들어지지 않았다.** J102(리본 커넥터)의 핀 1·2 는 미연결이고,
전원은 **별도 2핀 헤더 J101** 로 외부에서 3.3 V 를 받는다.

그래서 킷의 5 V 를 끌어와도 **쓸 데가 없다** — 3.3 V 를 만들 레귤레이터가 BOM 에
없다(U102=1.8 V, U103=0.9 V 뿐).

**결과: 전원 도메인이 둘이 된다.** 그 대가는 아래 3 절.

## 2. 레벨 변환 — `SN74LXC8T245` x2

`hanback_kit.md` 4.2 (2) 가 검토한 것은 `SN74AVCH16T245` 였는데 **실제로는 다른
부품**이다. 8비트짜리 두 개로 16채널을 만든다.

| | 문서가 검토한 것 | 실제 |
|---|---|---|
| 부품 | SN74AVCH16T245 | **SN74LXC8T245 x2** |
| 버스홀드 | 있음 | **없음** |
| 슈미트 트리거 | 없음 | **있음** |

**두 변화 다 우리에게 유리하다.**

- 버스홀드가 없어져 비교기가 이길 것이 없다. AVCH 에서는 ~200 uA 과구동이
  필요했고 그게 LPV7215 여유의 40% 였다.
- 대신 **슈미트 트리거**가 히스테리시스를 준다. `docs/ICD.md` 7 의 9번 걱정
  (*"LPV7215 에 내부 히스테리시스가 없다"*)을 이쪽이 덮는다. 보장되는 최소치는
  `VT+min - VT-max` = 0.76 - 0.69 = **70 mV** 로 크진 않지만 0 이 아니다.

### 문턱 검산 (데이터시트 SCES916A 6.5 표)

A 측 데이터 입력은 `VCCI`(= VCCA = 1.8 V) 기준이다.

| VCCA | `VT+` max | `VT-` max |
|---|---|---|
| 1.65 V | 1.13 V | 0.69 V |
| 2.3 V | 1.56 V | 0.97 V |

표에 1.8 V 행이 없어 보간했다. `VT+/VCCI` 비가 그 구간에서 일정하다
(1.13/1.65 = 0.685, 1.56/2.3 = 0.678):

```
VT+ (max) @ VCCA 1.8 V  ~=  0.68 x 1.8  =  1.23 V
```

| | |
|---|---|
| 비교기 LPV7215 @1.8 V 최악 `VOH` | **1.63 V** |
| 시프터 `VT+` max @1.8 V | ~**1.23 V** |
| **여유** | **+400 mV** |

**보간값임을 명시한다.** 보수적으로 1.65 V 행(1.13 V)을 써도 통과하므로
(여유 +500 mV) 결론은 안 바뀐다.

### 그 밖에 확인한 것

- `DIR` -> 1.8 V (H) = **A -> B**. 비교기 -> FPGA 방향, 맞다 (8.4 Table 8-1)
- 동적 풀다운 100 kohm 은 **device 가 disable 될 때만 잠깐** 활성 (8.3.1.1).
  정상 동작 중 비교기가 이길 것이 없다
- B 측에 직렬 33 ohm (R104~R119). 킷에도 33 ohm 이 있어 합 66 ohm.
  FPGA 입력이 고임피던스라 DC 강하 0

## 3. `SHFT_OE` = `JP101` 점퍼 ★

오래 "이 신호가 어디서 오는가" 가 미결이었다. 거버가 답했다:

```
TO.P,JP101,1,A_1   -> TO.N,1.8V
TO.P,JP101,2,C_2   -> TO.N,/SHFT_OE   --> U104 핀22 (OE), U105 핀22 (OE)
TO.P,JP101,3,B_3   -> TO.N,GND
```

**3핀 헤더의 가운데가 두 시프터의 `OE` 에 직결돼 있고 양옆이 1.8 V 와 GND 다.**
손으로 고르는 스위치다.

| 캡 위치 | `SHFT_OE` | `OE` (액티브 로우) | 시프터 |
|---|---|---|---|
| **1-2** (1.8 V) | H | H | **Isolation** — 양쪽 Hi-Z |
| **2-3** (GND) | L | L | **인에이블** (A->B) |
| 캡 없음 | 뜸 -> 내부 5 Mohm 풀다운 | L | 인에이블 |

> **정상 동작은 2-3 이다.**

### ⚠️ BOM 설명 문구에 속지 말 것

`KWS_Layout.csv` 의 `JP101` 행에 *"Jumper, 3-pole, **pins 1+2 closed/bridged**"*
라고 적혀 있다. 이건 **KiCad 심볼의 기본 설명 텍스트**지 보드 지시가 아니다.
그대로 1-2 에 꽂으면 `OE = H` 로 **격리**되어 FPGA 가 아무것도 못 본다.
증상은 "cmp 가 전부 0" 이고, 원인이 점퍼라는 것을 떠올리기 어렵다.

### 이 점퍼가 전원 순서 문제의 답이다

1 절에서 전원 도메인이 둘이 됐다. 그러면 **AFE 는 켜져 있고 킷이 꺼진** 상태가
생길 수 있고, 그때 3.3 V 가 `VCCO = 0` 인 FPGA 핀으로 들어간다. 절대 최대는
`VCCO + 0.55 V` (DS189) 이므로 채널당

```
(3.3 - 0.5) / (33 + 33) ~= 42 mA      x 16채널
```

가 ESD 클램프로 흐른다. FPGA I/O 클램프 허용은 보통 10 mA 대다.

**시프터의 `Ioff` 는 이 방향을 안 지켜준다** — 8.3.4 는 *"either supply < 100 mV
or floating"* 일 때만 Hi-Z 로 간다. 시프터 자기 전원이 멀쩡하면 FPGA 가 죽었는지
모르고 그냥 구동한다.

**그래서 `JP101` 을 1-2 로 옮기면 그 상태를 만들 수 있다.** 킷을 꺼둔 채 AFE 만
오래 켜야 할 때, 혹은 아날로그만 단독 시험할 때 쓴다.

> 3핀 헤더에 2핀 캡이라 1번과 3번이 동시에 물릴 수 없다. 1.8 V 가 GND 로 단락될
> 걱정은 구조적으로 없다.

## 4. 커넥터 매핑 — `J102`

```
비교기 k  ->  J102 핀 (33 + k)          k = 0..15   ->  핀 33 ~ 48
```

1:1 스트레이트 리본이므로 킷 J6 도 같은 핀 번호이고, `EXT = 핀 - 3` 이니:

```
cmp[k] -> EXT(30 + k)   ->  EXT30 .. EXT45
```

**16개가 전부 FPGA 뱅크 13 이다** (`rtl/probe_part.tcl`). 종전 우리 제안
(EXT0~15)은 뱅크 14 아홉 + 13 일곱으로 갈려 있었는데, 동료 배선이 우연히 한
도메인으로 떨어졌다. VCCO 가 양쪽 다 3.3 V 라 전기적 차이는 없지만 도메인이
하나면 더 안전하다.

| J102 핀 | 내용 |
|---|---|
| 1, 2 | **미연결** (킷에서는 VCC5V) |
| 3 ~ 32 | 미연결 |
| **33 ~ 48** | **비교기 0 ~ 15** |
| 49, 50 | GND |

`rtl/constraints/kws_top.xdc` 의 `set CMP_EXT0 30` 한 줄이 이것을 담는다.
배선이 또 바뀌면 그 숫자만 고치면 되고 **RTL 도 가중치도 .hex 도 안 바뀐다** —
`docs/ICD.md` 가 존재하는 이유다.
